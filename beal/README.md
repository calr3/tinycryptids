# A Turing machine for Beal's conjecture

**Current best: `machines/beal_135.txt`, a 135-state, 2-symbol Turing machine**
(named-state format, see `../tools/tm.py`). Started on a blank tape, it **halts iff Beal's
conjecture fails**: iff `a^x + b^y = c^z` for some `a, b, c ≥ 1` and `x, y, z ≥ 3` with
`gcd(a, b) = 1`. Lean proves this (`TM.Beal.M135.halts_iff`):

    Halts M135.delta2 M135.start2 ↔
      ∃ a b c x y z, 1 ≤ a ∧ 1 ≤ b ∧ 1 ≤ c ∧ 3 ≤ x ∧ 3 ≤ y ∧ 3 ≤ z ∧ Nat.gcd a b = 1 ∧ a ^ x + b ^ y = c ^ z

`RECORDS.md` lists the machines, and `PROOF.md` walks through the proof in plain words.

The 135-state machine is obtained in two stages:

1. `beal.txt` is the readable **225-state design**, generated by `build.py`. The Lean proof is
   written for this machine (`TM.Beal.halts_iff`).
2. `../tools/minimize.py` merges states of the design that never disagree on a transition the
   run uses (an exact SAT search; `kissat404`). `gen_reduced_lean.py` carries the theorem
   over, and `machines/beal_135_annotated.txt` is the same machine with each state named after
   its roles in the design.

The design follows `../fermat/` (the power routine, the zig-zag compare and the NEXCOM
enumeration are Fermat's), with three exponents instead of one and a coprimality test.

## The search

    for each (x, y, z, a, b, c) in NEXCOM order (every tuple, x, y, z ≥ 3, a, b, c ≥ 1):
        if gcd(a, b) = 1 and a^x + b^y = c^z: HALT

**gcd without division.** `gcd(a, b) = 1` iff the walk `0, a, 2a, …` modulo `b` reaches `1`
before it returns to `0` (the test of `../carmichael/`). Two holes, one in a and one in b, tick
in lockstep, each wrapping at its block's end; whenever a's hole wraps (every `a` ticks), b's
hole on its first position means coprime, on its last means not coprime.

## How it works

The tape, left to right (blocks of 1s, separators `0 0`, a hole is a single `0`):

    x 00 y 00 z 00 a 00 b 00 c 00 M 00 A 00 R 00 Q

* **Exponents** x, y, z: blocks of `E + 1` cells; a cursor runs over cells `1 .. E`. On the last
  cell it sits next to a separator (three 0s in a row), which the parsers, counting 0s modulo 2,
  still read as a hole; they only meet it from the right. x keeps a hole on cell 1 between
  tuples (the anchor), which is also the exponent cursor of the first power.
* **Bases** a, b, c: blocks of `β + 3` cells; a cursor runs over cells `2 .. β + 1`.
* All six blocks have minimum length 4; NEXCOM enumerates the lengths minus 4.
* **M** is a 1-cell marker, **A** accumulates `a^x + b^y`, **R** is the running power, **Q** scratch.

Per tuple:

1. **Walk** (`gA`, `gB`, `GK`, `WA`, `WB`, `BW`, `WW`, `TC`). Holes on a's and b's first
   positions; ticks as above. Not coprime: b's hole is gone, a's is taken away by the routine
   that also ends an unequal compare (`HE`, `X1`, home), and the next tuple follows. Coprime:
   a's hole stays as the base cursor.
2. **Powers** (Fermat's routine). R := 1, then E rounds of R := R·β (copy R β − 1 times onto Q,
   merge). When the exponent cursor wraps, it moves on to cell 1 of the next block (x → y → z,
   and finally into a), and the base cursor moves to the next block (a → b → c → M). R is
   added into A after the first two powers.
3. **Compare.** A zig-zag erases A and R cell by cell: equal → HALT. Otherwise the stack is
   cleared, A restored, the cursor left in a is filled, and the machine goes home and puts the
   anchor back on x's cell 1.

The seed writes the tuple `(4, 3, 3, 1, 1, 1)` (one past the all-minimal tuple; neither is a
solution) and enters the enumeration.
