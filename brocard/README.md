# A Turing machine for Brocard's problem

**Current best: `machines/brocard_61.txt`, a 61-state, 2-symbol Turing machine**
(named-state format, as in `../fermat`). Started on a blank tape, it **halts iff
n! + 1 = m² has a solution with n ≥ 8**, i.e. a solution beyond the three known
ones (n = 4, 5, 7). Lean proves this (`TM.Brocard.M61.halts_iff`):

    Halts M61.delta2 M61.start2 ↔ ∃ n m, 8 ≤ n ∧ fact n + 1 = m * m

where `fact` is the factorial (`TinyCryptids.fact`, `../lean/TinyCryptids/Defs.lean`). `RECORDS.md` lists
every machine with its state count and Lean theorem. `PROOF.md` walks through the proof in plain words.

(A machine that halts iff *some* solution exists would halt at n = 4, so the
open question is whether a fourth solution exists; none exists for n ≤ 10⁹.)

The 61-state machine is obtained in two stages:

1. `brocard.txt` is the readable **98-state design**, generated by `build.py`.
   The Lean proof is written for this machine (`TM.Brocard.halts_iff`).
2. `minimize.py` merges states of the design that never disagree on a transition
   the run uses (an exact SAT search), giving 61 states. `gen_reduced_lean.py`
   carries the theorem over. `machines/brocard_61_annotated.txt` is the same
   machine with each state named after its roles in the design, every transition
   commented.

## How it works

Tape layout (blocks of 1s separated by `00`):

    W 00 N 00 F 00 S      during the square test
    W 00 N 00 F 00 Q      during the multiplication

* **F** holds n! (n!+4 cells). **N** holds n. **W** is a 7-cell countdown: the
  rounds n = 1 .. 7 skip the square test (the seed cannot write 8! = 40320 cells,
  so F is built up from 1!).
* **Holes.** A hole is a single 0 inside a block, used as a counter. A hole is
  never next to a separator, so 2-state parsers do all navigation.
* **Square test** (n ≥ 8). n!+1 is a square iff it is a sum 1 + 3 + 5 + … of
  consecutive odd numbers. The F hole counts units of n!+1. **S** holds the odd
  number being subtracted, with a cyclic hole. Each step uses one unit and
  advances the S hole. When the S hole wraps around, S grows by 2 (the next odd
  number). When F runs out, n!+1 is a square iff the S hole has just wrapped:
  then the machine **halts**.
* **Multiplication.** F := (n+1)·F by n copies of F's n! cells onto Q (copy
  cursor in F, counter hole in N), then Q is merged into F. N grows by one cell
  into W.

The seed writes `1111111 00 101 00 11101` (W, N = 1, F = 1!), with the
multiplication of round 1 already set up.

State budget of the 98-state design: seed 19, square test 30, multiply 21,
merge and gate 16, test setup 12. After merging, every seed state is also a step
of another routine.

## Files and checks

* `build.py` generates the design (`python3 build.py brocard.txt`).
* Shared tools in `../tools/`: `tm.py` parses the format and converts it to
  bbchallenge standard text (`python3 ../tools/tm.py machines/brocard_61.txt`); `sim.c` is a fast
  simulator (`gcc -O2 -o ../tools/sim ../tools/sim.c`); `same_run.py A B k`
  checks that two machines have identical tapes after 10^3 .. 10^k steps;
  `minimize.py` (exact SAT) and `greedy_merge.py` merge states; `leangen.py`
  writes the generated Lean files.
* `test_e2e.py`: after each round up to n = 8 the tape holds |F| = n!+4, |N| = n+2
  and the right W. Variants that start the test earlier halt at the known
  solutions: from n = 4 at 4!+1 = 5², from n = 5 at 11², from n = 6 or 7 at
  7!+1 = 71² (S then holds 2m+1). The machine runs past 10⁹ steps.
* `gen_lean.py` writes `../lean/TinyCryptids/Brocard/Machine.lean` (the design);
  `gen_reduced_lean.py machines/brocard_61.txt M61` writes `M61.lean`;
  `annotate.py`: the readable listing.
* The proof: `../lean/TinyCryptids/Brocard/` (see `../lean/README.md`).
