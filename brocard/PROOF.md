# The proof, in plain words

This is a guided tour of the Lean proof that the 61-state machine
`machines/brocard_61.txt` halts if and only if Brocard's equation `n! + 1 = m²` has a solution
with `n ≥ 8` — a solution beyond the three known ones, `n = 4, 5, 7`. The hand-written proof is
about 500 lines in `../lean/TinyCryptids/Brocard/` (`Spec.lean`, `Tac.lean`, `Round.lean`,
`Main.lean`); the machine tables `Machine.lean` and `M61.lean` are generated. Each step below
names the lemma that carries it.

## What is proved

```lean
theorem TM.Brocard.halts_iff :
    Halts delta start ↔ ∃ n m, 8 ≤ n ∧ fact n + 1 = m * m

theorem TM.Brocard.M61.halts_iff :
    Halts M61.delta2 M61.start2 ↔ ∃ n m, 8 ≤ n ∧ fact n + 1 = m * m
```

* `fact` is the factorial: `fact 0 = 1`, `fact (n + 1) = fact n * (n + 1)`
  (`TinyCryptids.fact`, `../lean/TinyCryptids/Defs.lean`).
* `delta` is the 98-state design `brocard.txt` (generated by `build.py`, transcribed by
  `gen_lean.py` into `Machine.lean`), `start` is its first state on a blank tape. `delta2` is
  the 61-state machine `machines/brocard_61.txt` (`M61.lean`), `start2` likewise.
* `Halts δ c` means: started in configuration `c`, the machine reaches a configuration with
  no transition (`../lean/TinyCryptids/Core/Basic.lean`, the model shared by every machine in the
  repository: 2 symbols, a two-way infinite tape, the head always moves).
* So the right-hand side says: `n! + 1` is a perfect square for some `n ≥ 8`. The bound 8
  excludes exactly the known solutions (`4! + 1 = 5²`, `5! + 1 = 11²`, `7! + 1 = 71²`; the
  cases `n ≤ 3` give 2, 2, 3, 7, which are not squares anyway).

To trust the result you need to trust the Lean kernel, the definitions above, and the listing
of the machine. Nothing else: both theorems depend only on Lean's standard axioms `propext`,
`Classical.choice` and `Quot.sound` (`../lean/Check.lean` prints this).

The proof has four parts: arithmetic (`Spec.lean`), the machine's routines on the tape
(`Round.lean`, using the step tactics of `Tac.lean` and the generic parsers of `Core/`), the main
theorem for the 98-state design (`Main.lean`), and the transfer to the 61-state machine
(`M61.lean`).

## The idea

The machine runs **rounds** `n = 1, 2, 3, …`, keeping `n!` on the tape in unary:

    F := 1!                                   (written by the seed)
    for n = 1, 2, 3, …:
      if n ≥ 8: if F + 1 is a square: HALT
      F := F + n·F                            (= (n + 1)!, by n copies of F)

Two unary tricks do all the arithmetic. **The square test** uses `1 + 3 + 5 + … + (2j + 1) =
(j + 1)²`: the machine spends the `n! + 1` units of `F + 1` one at a time, while a second
counter walks through the odd numbers 1, 3, 5, …; `n! + 1` is a square exactly when the units
run out at the moment an odd number has been used up completely. **The factorial** is built by
copying: `(n + 1)! = n! + n · n!`, so the machine appends `n` copies of `F`'s `n!` cells to a
scratch block `Q` and then merges `Q` into `F`. **The warm-up**: the test is skipped for
`n < 8` — otherwise the machine would halt at `n = 4` — by a countdown block `W` of 7 cells
that loses one cell per round; the test runs only once `W` is empty. (The seed cannot write
`8! = 40320` cells directly, so `F` has to be grown from `1!` anyway.)

There is no subtle mathematics: the proof is a careful account of the tape. The one piece of
number theory is that no square lies strictly between two consecutive squares.

## Part 1: arithmetic (`Spec.lean`)

**Lemma 1 (`fact_pos`, `fact_succ'`).** `n! ≥ 1`, and `(n + 1)! = n! + n · n!` — the form in
which the copying multiplication produces the next factorial.

**Lemma 2 (`sq_succ`).** `(j + 1)² = j² + (2j + 1)`.

**Lemma 3 (`not_square_between`).** If `1 ≤ c < 2j + 1`, then `j² + c` is not a square.
*Proof:* if `j² + c = m²`, then `m > j` gives `m² ≥ (j + 1)² = j² + 2j + 1 > j² + c`, and
`m ≤ j` gives `m² ≤ j² < j² + c`.

## Part 2: the machine on the tape (`Round.lean`)

**The tape.** The tape consists of blocks of 1s separated by `00`:

    W 00 N 00 F 00 S      during the square test
    W 00 N 00 F 00 Q      during the multiplication

* `W`: `w` ones, the warm-up countdown (empty in every test round).
* `N`: `n + 2` cells, the round number `n`. During the multiplication it has a hole at cell
  `a + 1`, counting the copies made.
* `F`: `v + 4` cells, where `v = n!`. During the test it has a hole at cell `u + 1`, counting
  the units used; during the multiplication a hole at cell `b + 3` is the copy cursor.
* `S`: `d + 2` cells, the odd number `d`, with a cyclic hole at cell `c + 1`.
* `Q`: `q` ones, the copies made so far.

Cells of a block are numbered from 0. A **hole** is a single 0 inside a block, never at its
first or last cell, so it is never next to a separator. This makes navigation cheap: a
two-state **parser** moves over 1s, skips a `00` pair, and stops just past a lone 0
(`ParserR`, `ParserL`, with `ParserR.find`, `ParserL.find` for any "clean" stretch of tape —
one whose runs of 0s all have length exactly two, `Clean` — and the special cases
`ParserR.find2`, `ParserL.find2`, `ParserR.find0`, `ParserL.find0` in `Core/Routines.lean`).
The design has five parsers (`PPS`, `PPK`, `PPP`, `PPB`, `PPN`), each checked by computation.

In Lean, a configuration is a state with the tape left of the head and the tape from the head
on, each as a stream of cells; `ones k s` is `k` cells of 1 followed by `s`. Most lemmas below
are proved by stepping the machine one transition at a time (the tactics `gR`, `gL` of
`Tac.lean`) and jumping over long runs of 1s or 0s with `scanR`, `scanL`, `scanR0`, `scanL0`,
`eraseR`, `eraseL` (`Core/Lemmas.lean`). The checkpoints are:

* `TP n v u d c` — the square test: head on the `F` hole at cell `u + 1`, state `p1`; `S` has
  `d + 2` cells with its hole at `c + 1`; nothing (blank) left of `N`.
* `G n w a v q` — the multiplication, about to start copy number `a + 1`: the `N` hole at cell
  `a + 1`, state `g1`, `Q` holding `q` ones.
* `X n w a v b q` — the copy loop: cursor at cell `b + 3` of `F`, head on the separator
  right of `F`, state `x1`.
* `MG n w v q` — all copies made, head on the separator between `N` and `F`, state `m1`.

### The square test

The test of `v + 1` keeps the invariant `u = j² + c`, `d = 2j + 1`, `0 ≤ c < d`: `u` units are
used, the odd numbers `1, 3, …, 2j − 1` are used up (that is `j²` units) and `c` units of the
current odd number `d = 2j + 1` are used. Each unit moves the `F` hole one cell right
(states `p1`–`p4`), then the parser `PS` finds the `S` hole and moves it one cell right:

| situation | what the machine does | lemma |
|---|---|---|
| `c + 1 < d` | the `S` hole moves on: `TP n v (u+1) d (c+1)` | `test_step` |
| `c = d − 1` (hole at the last inner cell) | wrap: `S` grows by two cells and its hole goes back to cell 1: `TP n v (u+1) (d+2) 0` — now `u + 1 = (j + 1)²` | `test_wrap` |
| `u = v + 1`, `c = 0` | no unit left and the `S` hole at cell 1: **the machine halts** (state `k3` reads the separator two cells left of the hole) | `test_halt` |
| `u = v + 1`, `c ≥ 1` | no unit left: erase `S`, put the `N` hole at cell 1, go to the multiplication: `G n 0 0 v 0` | `test_no` |

When `F`'s hole reaches cell `v + 2`, filling it exposes the separator, which signals "no unit
left" (`p3` on 0 goes to the parser `PK`). So `u` runs exactly from 0 to `v + 1`.

**Lemma 4 (the whole test, `test_all`, in `Main.lean`).** Starting from any `TP n v u d c`
satisfying the invariant: if `v + 1` is a square, the machine reaches the halting state
(`HaltAt`); if not, it reaches `G n 0 0 v 0`. *Proof:* induction on the units left,
`v + 1 − u`, with one `test_step` or `test_wrap` per unit (Lemma 2 keeps the invariant across a
wrap). At the end `u = v + 1 = j² + c`: if `c = 0`, `v + 1 = j²` is a square and `test_halt`
applies; if `c ≥ 1`, Lemma 3 says `v + 1` is not a square and `test_no` applies. In each case
the other alternative is contradictory.

### The factorial by copying

**Lemma 5 (copying, `g_to_x`, `copy_one`, `copy_last_next`, `copy_last_done`, `copies`).**
The cursor runs over the `v` cells `3 … v + 2` of `F`; each position appends one 1 to `Q`:

| step | what the machine does | lemma |
|---|---|---|
| start of a copy | scan `N`, put the cursor at cell 3 of `F` | `g_to_x` |
| cursor not at the last cell | append a 1 to `Q`, parser `PB` back to the cursor, move it one cell right | `copy_one` |
| cursor at the last cell, copies left | append a 1, parser `PN` to the `N` hole, move it one cell right: next copy | `copy_last_next` |
| cursor at the last cell, `N` hole at cell `n` | append a 1, fill the `N` hole: to the merge | `copy_last_done` |

`copies` chains these by induction on the remaining work `(n − 1 − a) · v + (v − 1 − b)`.
So `multiply`: from `G n w 0 v 0` the machine reaches `MG n w v (n · v)` — `n` copies of `v`
cells (both `n, v ≥ 1`). The `N` hole is filled again at the end.

**Lemma 6 (merge, `merge_pre`).** From `MG n w v q` (`q ≥ 1`) the machine fills the separator
between `F` and `Q` with two 1s and erases two 1s at the far end of `Q`, so `F` becomes one
block of `v + q + 4` cells; then it walks left and grows `N` by one cell into the separator on
its left, and that separator moves one cell into `W` (`N` now has `(n + 1) + 2` cells). It
stops in state `v3` on the last cell of `W` (`mult_round` in `Main.lean` composes Lemmas 5–6).

With `v = n!` and `q = n · n!`, `F` now holds `n! + n · n! = (n + 1)!` (Lemma 1).

### The gate: warm-up or test

State `v3` erases one cell of `W` and `v4` looks at the next one:

| `W` | what the machine does | lemma |
|---|---|---|
| `w + 2` cells (one is left after the erase) | warm-up: put the `N` hole at cell 1, start the next multiplication: `G (n + 1) (w + 1) 0 v 0` | `gate_warm` |
| 0 or 1 cells | test: put the `F` hole at cell 1, write `S = 101` (`d = 1`, hole at cell 1), parser `PP` back to the `F` hole: `TP (n + 1) v 0 1 0` | `gate_test` |

**The seed** (`seed_reach`). States `seed0`–`seed18` write `1111111 00 101 00 11101`: `W` of 7
cells, `N` for `n = 1` with its hole at cell 1, `F = 1!` with the cursor at cell 3, and end on
the separator right of `F` — the configuration `X 1 7 0 1 0 0`, round 1's multiplication
already under way.

## Part 3: the main theorem for the design (`Main.lean`)

Write `RS n` for `TP n (n!) 0 1 0`, the start of the test round for `n`.

**Lemma 7 (a test round, `round`).** For `n ≥ 1`: if `n! + 1` is a square, the machine halts
from `RS n`; otherwise it strictly reaches `RS (n + 1)`. *Proof:* Lemma 4 with
`u = j = c = 0`, then `mult_round` (with `w = 0`) and `gate_test`, using
`(n + 1)! = n! + n · n!`. "Strictly" (at least one step, `Reach1`) follows from
`RS n ≠ RS (n + 1)` (`RS_ne`: the two tapes differ at one cell, since `N` has a different length)
and `reach1_of_ne`.

**Lemma 8 (the warm-up, `warm`, `start_reach`).** From `start` the machine reaches `RS 8`.
*Proof:* the seed gives round 1's copy loop; round 1 is finished by `copies` and `merge_pre`,
and `gate_warm` leaves `W` with 6 cells and starts round 2. `warm` handles rounds
`n = 2, …, 7` by induction on `w = 8 − n` (the cells of `W` at the start of round `n`): each
round is `mult_round` followed by `gate_warm`, except round 7 (`w = 1`), whose `gate_test`
starts the test with `F = 8!`, i.e. `RS 8`. No square test runs in rounds 1–7, so the
solutions `n = 4, 5, 7` are never seen.

**Halting gives a solution.** Suppose the machine halts but no `n ≥ 8` has `n! + 1` square.
Then by Lemma 7 every `RS n` with `n ≥ 8` strictly reaches `RS (n + 1)`, so the machine never
halts from `RS 8` (`not_halts_of_progress`). Since the machine is deterministic and `start`
reaches `RS 8` (Lemma 8), halting from `start` would mean halting from `RS 8`
(`halts_det`) — contradiction.

**A solution makes it halt** (`haltAt_of_sol`). Let `N ≥ 8` with `N! + 1 = M²`. From `RS 8`,
apply Lemma 7 round by round: each round either halts (done) or passes to the next, and round
`N` halts. By induction on `N − n`, the machine reaches its halting state from `RS 8`, hence
from `start` (`HaltAt.back`, `HaltAt.halts`). Here `HaltAt c` means: from `c` the machine reaches
the explicit state `halt`, which has no transitions.

This is `TM.Brocard.halts_iff`, for the 98-state design `brocard.txt`.

## Part 4: the 61-state machine (`M61.lean`)

`M61` is obtained from the design by merging states that never disagree on a transition the
run uses (`minimize.py`, an exact SAT search). `M61.lean` is generated by
`gen_reduced_lean.py`: it gives the merged table `delta2`, a map `phi` from design states to
merged states, and a check `compat` (one case per transition, closed by computation) that
`delta2 (phi q) b` does what `delta q b` does wherever the latter is defined. The generic
lemma `halts_iff_of_sim` (`Core/Basic.lean`, using `sim_run`) then shows that the merged machine
follows the design's run step for step and halts exactly when it does. The one extra fact it
needs — that where the design halts the merged machine halts too — comes from
`haltAt_of_sol`: the design halts only in state `halt`, which `phi` maps to `halt2`, and
`delta2 halt2` is undefined. The merged machine's other undefined transitions (`---` in the
listing) are ones the design's run never uses.

## What the proof does not cover

* It says nothing about whether a fourth solution exists — that is the open problem (none
  exists for `n ≤ 10⁹`). If there is none, the machine runs forever, and the proof shows
  exactly that.
* Only `n ≥ 8` is covered. The variants of `build.py` that start the test earlier (and halt at
  `n = 4`, `5` or `7`), used in `test_e2e.py`, are tested by simulation, not proved in Lean.
* The arithmetic is unary: the square test of round `n` takes at least `n!` steps and the
  copying about `n · n!` cell trips, so the machine checks only small `n` in any feasible run.
  The proof is about halting, not running time.
* The bbchallenge standard-text line in `README.md` and the annotated listing
  `machines/brocard_61_annotated.txt` are printed from the same machine file; `annotate.py`
  checks the listing is the same machine.
