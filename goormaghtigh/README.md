# A Turing machine for the Goormaghtigh conjecture

**Current best: `machines/goormaghtigh_53.txt`, a 53-state, 2-symbol Turing machine**
(named-state format, see `../tools/tm.py`). Started on a blank tape, it **halts iff the
Goormaghtigh conjecture is false**: iff some value other than 31 and 8191 is a repunit of
length at least 3 in two bases. Lean proves this (`TM.Goormaghtigh.M53.halts_iff`):

    Halts M53.delta2 M53.start2 ↔ ∃ x y m n, 1 < y ∧ y < x ∧ 2 < m ∧ 2 < n ∧
      rep x m = rep y n ∧ rep x m ≠ 31 ∧ rep x m ≠ 8191

with `rep b m = 1 + b + … + b^(m−1)` from `../lean/TinyCryptids/Defs.lean`
(`31 = rep 2 5 = rep 5 3`, `8191 = rep 2 13 = rep 90 3`). `RECORDS.md`
lists the machines, and `PROOF.md` walks through the proof in plain words.

The 53-state machine is obtained in two stages:

1. `goormaghtigh.txt` is the readable **73-state design**, generated by `build.py`. The Lean
   proof is written for this machine (`TM.Goormaghtigh.halts_iff`).
2. `../tools/minimize_clique.py` merges states of the design that never disagree on a
   transition the run uses (an exact SAT search; 52 states are unsatisfiable, so 53 is optimal
   for this design). `gen_reduced_lean.py` carries the theorem over, and
   `machines/goormaghtigh_53_annotated.txt` is the same machine with each state named after its
   roles in the design.

## How it works

The machine needs neither constant: it checks `V = 4, 5, 6, …` and counts the *bad* values,
those that are repunits (of length ≥ 3) in two bases. 31 and 8191 are the first two, so a
third exists iff the conjecture fails, and the machine halts after the third.

For each `V` and each base `b = 2 … V − 2` it walks `r = 1, b + 1, b² + b + 1, …`
(`r := r·b + 1`) until `r ≥ V`; a **hit** is `r = V`. A repunit of length 1 or 2 would be
`V = 1` or `b = V − 1`, so every hit has length ≥ 3. Tape (blocks of 1s):

    F 0^(1+f) Vb 00 Rg

* **The region Rg** (`V + 1` cells, the rightmost block) holds `r` and `V − r` at once:
  `R H D`, `r` ones, the hole H, `V − r` ones. A step `r := r·b + 1` turns H into a marker M
  and punches a new H on D's first cell, then makes `b − 1` passes; in a pass the copy cursor C
  walks R and each of its `r` cells moves H one cell right (a *tick*: fill H, punch the next
  cell). Filling M then merges R, M and the copies: `r + 1 + r(b − 1) = r·b + 1` ones before H.
  Copying and comparing are one motion: if H must move past the region's last cell,
  `r·b + 1 > V` (overflow, the base is done); if it ends on the last cell, `r = V` (a hit).
* **Vb** (`V` cells) holds the base as the position of its hole K: `b` cells right of K. It
  also counts the passes: a pass cursor P is punched on `K + 2` and moves one cell per pass
  until it falls off Vb's end. The next base moves K one cell left; when K would reach Vb's
  cell 0, all bases are done.
* **F** is the countdown: `4 − g − f` cells, where `g` is the number of bad values so far
  and `f = min(hits of V, 2)` is the number of F's last cells a hit has erased (the run of
  zeros before Vb has `1 + f` cells). At the end of `V`, Vb grows on the left, so F gets its
  `f` cells back and moves one cell left; after a bad value it gets only one back, and if F is
  then empty this was the third bad value: the machine **halts**. Then K goes on Vb's cell
  `V − 2` (`b = 2` for `V + 1`) and the region grows by one cell.

The seed writes `1111 0 1111 00 1111`: the tape of `V = 3` in the middle of its next-value
step, which builds the start of `V = 4`.

State budget of the 73-state design: seed 15, step (check, start, passes, ticks, merge) 23,
overflow 6, hit 9, next base 7, next value 13. After merging, every seed state does double
duty; 34 states of the other routines stay alone.

### Design notes

* The first design (78 states, 56 merged) erased F's last cell at the first hit of a value and
  F's first and last cells at the second, halting when F ran out (12 states for the hit). Now a
  hit only erases a cell while `f < 2`, and the halt is decided at the end of the value, when F
  gets its cells back (74 states, 54 merged).
* That design kept F right of the region, whose growth then had to move F. With F left of Vb,
  Vb grows into the run before F, the region grows freely at the right end, and the next-value
  step is two states shorter (73 states, 53 merged).
* Bases `b > √V` are walked too (one or two steps each); stopping at `b² + b + 1 > V` would
  need a step counter.
