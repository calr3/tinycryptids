# A Turing machine for Legendre's conjecture

**Current best: `machines/legendre_44.txt`, a 44-state, 2-symbol Turing machine**
(named-state format, as in `../fermat`). Started on a blank tape, it **halts iff
Legendre's conjecture is false**, i.e. iff for some n ≥ 1 there is no prime
strictly between n² and (n+1)². Lean proves this (`TM.Legendre.M44.halts_iff`):

    Halts M44.delta2 M44.start2 ↔ ∃ n, 1 ≤ n ∧ ∀ p, n ^ 2 < p → p < (n + 1) ^ 2 → ¬ Prime p

where `Prime p := 2 ≤ p ∧ ∀ d, d < p → 2 ≤ d → p % d ≠ 0`
(`TinyCryptids.Prime`, `../lean/TinyCryptids/Defs.lean`). `RECORDS.md` lists every machine with its state
count and Lean theorem. `PROOF.md` walks through the proof in plain words.

(A search can only halt when it finds a counterexample, so "halts iff the
conjecture is false" is the version that does not depend on the answer.)

The 44-state machine is obtained in two stages:

1. `legendre.txt` is the readable **71-state design**, generated by `build.py`.
   The Lean proof is written for this machine (`TM.Legendre.halts_iff`).
2. `minimize.py` merges states of the design that never disagree on a transition
   the run uses (an exact SAT search), giving 44 states. `gen_reduced_lean.py`
   carries the theorem over. `machines/legendre_44_annotated.txt` is the same
   machine with each state named after its roles in the design, every transition
   commented.

## How it works

The machine tests m = 2, 3, 4, ... in turn. Interval n is m = n² .. n² + 2n
(for n = 1 only 2, 3). n² is never prime, so the interval contains a prime iff
(n², (n+1)²) does. Tape layout (blocks of 1s separated by `00`):

    [1 0] Q 00 D 00 R

* **D** (d+2 cells) is the trial divisor d ≥ 2, **R** (r+2 cells) is r = m − d.
  Moving the separator between them one cell to the right steps d → d+1.
* **Holes.** A hole is a single 0 inside a block, used as a counter. A hole is
  never next to a separator, so 2-state parsers do all navigation.
* **Trial division (mod walk).** r times: advance the D hole one cell (wrapping
  around), then the R hole. When the R hole runs off the end, d | m iff the D
  hole is back at its first cell. If d | m, m is composite. Otherwise d := d+1.
  If r reaches 0, m is prime.
* **Q and the flag.** Q has 2n+3 cells; its hole marks the position of m in the
  interval. A prime sets a flag: a 1 two cells left of Q. After each m the Q
  hole moves on. When it runs off Q the interval is over: the machine **halts**
  if the flag is not set. Otherwise the flag and the 0 next to it are already
  the first two cells of the next interval's Q (2n+5 cells, hole at cell 1).
* **Rebuild.** D := 2 and R := m − 1, for m + 1.

The seed writes `11011 00 1011 00 11`: interval 1 at m = 2.

State budget of the 71-state design: seed 15, mod walk 23, shift 7, prime 8,
advance Q 8, rebuild 10. After merging, every seed state is also a step of
another routine.

## Files and checks

* `build.py` generates the design (`python3 build.py legendre.txt`).
* Shared tools in `../tools/`: `tm.py` parses the format and converts it to
  bbchallenge standard text (`python3 ../tools/tm.py machines/legendre_44.txt`); `sim.c` is a fast
  simulator (`gcc -O2 -o ../tools/sim ../tools/sim.c`); `same_run.py A B k`
  checks that two machines have identical tapes after 10^3 .. 10^k steps;
  `minimize.py` (exact SAT) and `greedy_merge.py` merge states; `leangen.py`
  writes the generated Lean files.
* `test_e2e.py`: at every advance of Q (m = 2 .. 442) the tape is compared with
  a Python reference (n, k, m = d + r, flag). A test variant with intervals of 3
  numbers (1..3, 4..6, ...) halts on the first one without a prime, 25..27.
  The machine runs past 10^8 steps.
* `gen_lean.py` writes `../lean/TinyCryptids/Legendre/Machine.lean` (the design);
  `gen_reduced_lean.py machines/legendre_44.txt M44` writes `M44.lean`;
  `annotate.py`: the readable listing.
* The proof: `../lean/TinyCryptids/Legendre/` (see `../lean/README.md`).
