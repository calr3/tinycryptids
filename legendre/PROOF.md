# The proof, in plain words

This is a guided tour of the Lean proof that the 71-state design `legendre.txt` and the
44-state machine `machines/legendre_44.txt` halt if and only if Legendre's conjecture is
false. The proof is about 1050 lines in `../lean/TinyCryptids/Legendre/`, on top of the shared
machine model and routines in `../lean/TinyCryptids/Core/`; each step below names the lemma that
carries it.

## What is proved

```lean
theorem TM.Legendre.halts_iff :
    Halts delta start ↔ ∃ n, 1 ≤ n ∧ ∀ p, n ^ 2 < p → p < (n + 1) ^ 2 → ¬ Prime p

theorem TM.Legendre.M44.halts_iff :
    Halts delta2 start2 ↔ ∃ n, 1 ≤ n ∧ ∀ p, n ^ 2 < p → p < (n + 1) ^ 2 → ¬ Prime p
```

* `Prime p` is `2 ≤ p ∧ ∀ d, d < p → 2 ≤ d → p % d ≠ 0`: no `d` with `2 ≤ d < p` divides
  `p` (`TinyCryptids.Prime`, `../lean/TinyCryptids/Defs.lean`).
* `delta` is the 71-state design (plus a state `halt` with no transitions), generated by
  `gen_lean.py` from `legendre.txt` into `Machine.lean`; `delta2` is the 44-state merged
  machine (plus `halt2`) in `M44.lean`. `start` and `start2` are the first state on a blank
  tape.
* `Halts δ c` means: started in configuration `c`, the machine reaches a configuration with
  no transition (`../lean/TinyCryptids/Core/Basic.lean`, the model shared by every machine in the
  repository: 2 symbols, a two-way infinite tape, the head always moves).
* So the right-hand side says: some `n ≥ 1` has no prime strictly between `n²` and
  `(n + 1)²` — a counterexample to Legendre's conjecture. (`LegendreFails n` in `Spec.lean`
  is this predicate for one `n`.)

To trust the result you need to trust the Lean kernel, the definitions above, and the
listing of the machine. Nothing else: both theorems depend only on Lean's standard axioms
`propext`, `Classical.choice` and `Quot.sound` (`../lean/Check.lean` prints this).

The proof has four parts: arithmetic (`Spec.lean`), the routines of the machine on the tape
(`Round.lean`, with the one-step tactics of `Tac.lean` and the generic parsers and hole
advance of `Core/Lemmas.lean`, `Core/Routines.lean`), the main theorem for the design
(`Main.lean`), and the transfer to the 44-state machine (`M44.lean`).

## The idea

The machine tests `m = 2, 3, 4, …` for primality, in **intervals**: interval `n` is
`m = n², …, n² + 2n` (`2n + 1` numbers; for `n = 1` the seed starts at `m = 2`). `n²` is
never prime for `n ≥ 2`, so the interval contains a prime iff `(n², (n + 1)²)` does. A
flag records whether a prime has been seen in the current interval; when the interval ends
with the flag unset the machine halts, otherwise it clears the flag and goes on with
interval `n + 1`. Primality is tested by **trial division** by every `d = 2, …, m − 1`
(not only up to `√m`), each division done by a unary "mod walk". So the machine halts at
the first counterexample and only there; if there is none, it moves from interval to
interval forever.

## Part 1: arithmetic (`Spec.lean`)

**Lemma 1 (the interval, `fails_iff`).** For `n ≥ 2`, `LegendreFails n` holds iff none of
`n² + i`, `i < 2n + 1`, is prime. *Proof:* `(n + 1)² = n² + 2n + 1` (`sq_succ`), and the
extra number `n²` is not prime (`square_not_prime`: `n` divides it and `2 ≤ n < n²`).

**Lemma 2 (`not_fails_one`).** `n = 1` is not a counterexample: 2 is prime and
`1 < 2 < 4`. This lets the machine treat interval 1 specially in its seed.

**Lemma 3 (`mod_succ`, `add_mod_self_left'`).** `(x + 1) % d` is `x % d + 1` if that is
`< d` and `0` if it equals `d`; and `(d + x) % d = x % d`. These drive the mod walk: the
residue goes up one at a time and wraps, and `d ∣ m` iff `d ∣ m − d`.

## Part 2: the machine on the tape (`Round.lean`)

**The tape.** Blocks of 1s separated by two 0s:

    [1 0] Q 00 D 00 R

* **Q** has `q + 2` cells, `q = 2n + 1`, and a *hole* (a single 0) at cell `k + 1`: the
  machine is at the `k`-th number `m = n² + k` of interval `n`.
* **The flag** is a 1 two cells left of Q (the cell between is 0); no flag means blank
  there. `FL f` is this part of the tape and `QX q k f` is Q plus flag, read leftwards from
  Q's right end.
* **D** has `d + 2` cells and holds the trial divisor `d ≥ 2`; during the mod walk its hole
  at cell `c + 1` is a residue counter `c < d`.
* **R** has `r + 2` cells with `r = m − d`; during the mod walk a hole at cell `j` counts
  the steps walked.

A hole is never next to a separator, so the 2-state parsers `ParserR`/`ParserL`
(`Core/Lemmas.lean`, stated in `ones` form as `ParserR.find2`, `ParserL.find2`, `find0` in
`Core/Routines.lean`) can find "the next hole" by crossing separators. The design has eight
copies of them (`PPR`, `PPF`, `PPN`, `PPM`, `PPK`, `PPQ`, `PPC`, `PPP`), and one copy `Dma`
of the generic cyclic hole advance `Dadv` (`Dadv.nowrap`, `DW.wrap`), each checked by `rfl`
against `delta`.

The configurations used as checkpoints (`X` is the tape left of D's separator, between
candidates `X = QX q k f`):

| name | meaning |
|---|---|
| `MW X d r c j` | mod walk: about to advance the D hole (residue `c`); R hole at cell `j` |
| `SH X d r` | `d ∤ m`: D hole reset to cell 1, about to shift |
| `SHT X d r` | head on cell 0 of R, D hole at cell 1, R without hole: start of a trial division |
| `P6 X d` | `r = 0`: head two cells past R |
| `AQ q k f d r` | head on the Q hole, about to advance it |

**Lemma 4 (one step of the mod walk, `mw_step`).** If `c < d` and `1 ≤ j < r`, `MW X d r c j`
reaches `MW X d r ((c + 1) % d) (j + 1)`: the D hole moves one cell (`Dadv.nowrap`) or wraps
from cell `d` back to cell 1 (`DW.wrap`), then a parser finds the R hole and moves it one
cell right, and a parser returns to D. Iterating (`mw_upto`, in `Main.lean`): `MW X d r 0 1`
reaches `MW X d r ((j − 1) % d) j` for `1 ≤ j ≤ r`.

**Lemma 5 (end of the mod walk).** At `j = r` the last advance makes the residue `r % d`
and the R hole runs off R. The parser `PK` goes back to the D hole and the state `k1` looks
two cells left of it (the separator 0 if and only if the hole is at cell 1):

| residue after the walk | what the machine does | lemma |
|---|---|---|
| `≠ 0` (hole not at cell 1) | fill the hole, put it back at cell 1: `SH X d r` | `mw_last_nodiv` |
| `= 0` (hole at cell 1, `d ∣ m`) | `m` is composite; go left to the Q hole: `AQ q k f d r` | `mw_last_div` |

**Lemma 6 (shift, `shift`, `tail_more`, `tail_zero`).** From `SH X d r` with `r ≥ 1`, moving
the separator between D and R one cell right gives `SHT X (d + 1) (r − 1)`. From `SHT X d r`:
if `r ≥ 1`, the machine makes the R hole at cell 1 and reaches `MW X d r 0 1`; if `r = 0`, it
reaches `P6 X d`.

**Lemma 7 (prime, `prime_path`).** From `P6 (QX q k f) d` (`k < q`), the machine passes the D
hole, finds the Q hole, runs to Q's left end, writes the flag (whether or not it was set),
and comes back: `AQ q k true d 0`.

**Lemma 8 (next candidate).** From `AQ q k f d r` (`d ≥ 2`) the Q hole moves one cell right;
then `rebuild` sets `D := 2` and `R := d + r − 1`, i.e. the tape for `m + 1`:

| position in the interval | what the machine does | lemma |
|---|---|---|
| `k + 1 < q` | `SHT (QX q (k + 1) f) 2 (d + r − 1)` | `qadv_next` |
| `k + 1 = q`, flag unset | runs to the flag cell, reads 0: **halts** | `qadv_end_halt` |
| `k + 1 = q`, flag set | the flag and the 0 next to it become cells 0, 1 of a Q with two more cells, hole at cell 1, flag cleared: `SHT (QX (q + 2) 0 false) 2 (d + r − 1)` | `qadv_end_next` |

`HaltAt c` means that `c` reaches the state `halt`; `HaltAt.back` and `HaltAt.halts` move it
back along a run and turn it into `Halts`. The machine has no other way to halt on the
configurations the proof visits.

**Lemma 9 (the seed, `seed_reach`).** The fifteen seed states write `11011 00 1011 00 11`
and land in the shift routine: `start` reaches `P6 (QX 3 1 false) 2`, i.e. interval 1, `m = 2`,
`d = 2`, `r = 0`.

## Part 3: the main theorem for the design (`Main.lean`)

**Lemma 10 (trial division, `test`).** Let `k < q`, `d ≥ 2`, and suppose no `e` with
`2 ≤ e < d` divides `d + r`. Then from `SHT (QX q k f) d r`:
* if `d + r` is prime, the machine reaches `AQ q k true (d + r) 0`;
* if not, it reaches `AQ q k f d' r'` for some `d' + r' = d + r`, `d' ≥ 2`.

*Proof*, by induction on `r`. For `r = 0` the hypothesis says exactly that `d` is prime, and
Lemmas 6 and 7 apply. For `r + 1`: Lemma 6 starts the mod walk, Lemma 4 runs it, and
Lemma 3 decides the residue. If `d ∤ d + r + 1`, Lemmas 5 and 6 reach `SHT … (d + 1) r`, the
no-divisor hypothesis now holds below `d + 1`, and the induction hypothesis applies. If
`d ∣ d + r + 1`, the number is not prime (as `d < d + r + 1`) and Lemma 5 gives the second
case directly.

**Lemma 11 (one candidate, `cand`).** Write `CS q k f m := SHT (QX q k f) 2 (m − 2)`, the
configuration before testing `m`, and `f' = f || Prime m`. Then from `CS q k f m`
(`m ≥ 2`, `k < q`): if `k + 1 < q` the machine reaches `CS q (k + 1) f' (m + 1)`; if
`k + 1 = q` and `f'` is set it reaches `CS (q + 2) 0 false (m + 1)`; if `k + 1 = q` and `f'`
is unset it halts. (Lemma 10 with `d = 2`, where the hypothesis is empty, then Lemma 8.)

**Lemma 12 (the rest of an interval, `ival`).** For an interval `[b, b + q)` (`b ≥ 2`), from
its `k`-th number `CS q k f (b + k)`: if `f` is set or some `b + i`, `k ≤ i < q`, is prime,
the machine reaches `CS (q + 2) 0 false (b + q)`; if `f` is unset and none is prime, it
halts. Induction on `q − k`, one `cand` per number.

**Lemma 13 (one interval, `interval`).** Let `IS n := CS (2n + 1) 0 false (n²)`, the start of
interval `n`. For `n ≥ 2`: if `LegendreFails n`, the machine halts from `IS n`; otherwise it
strictly reaches `IS (n + 1)`. *Proof:* Lemma 12 with `b = n²`, `q = 2n + 1`, Lemma 1, and
`n² + 2n + 1 = (n + 1)²`. "Strictly" (at least one step) is obtained from `IS n ≠ IS (n + 1)`
(`IS_ne`, which compares the tape cell at distance `n²`) and `reach1_of_ne`.

**Lemma 14 (start, `start_reach`).** `start` reaches `IS 2`: after the seed, 2 is handled
as a prime (`prime_path`), so the flag is set; 3 is tested (`test`; whether it is prime does
not matter, since the flag is already set); then `qadv_end_next` starts interval 2 at `m = 4`.

**Halting gives a counterexample.** Suppose there is no counterexample. Then by Lemma 13
every `IS n` (`n ≥ 2`) strictly reaches `IS (n + 1)`. A machine that keeps strictly moving
from one member of a family to another never halts (`not_halts_of_progress`,
`Core/Sys.lean`); since the machine is deterministic and `start` reaches `IS 2`, it does not
halt from `start` either (`halts_det`, i.e. `Halts.of_reach`).

**A counterexample makes it halt** (`haltAt_of_fails`). Take a counterexample `N`; `N ≥ 2`
by Lemma 2. By induction on `N − n`, the machine halts from `IS n` for every `2 ≤ n ≤ N`:
interval `n` either halts (if `n` is a counterexample) or passes to `IS (n + 1)`. With
Lemma 14 this gives `HaltAt start`, in the explicit state `halt`.

This is `TM.Legendre.halts_iff`.

## Part 4: the 44-state machine (`M44.lean`)

`M44` is obtained from the design by merging states that never disagree on a transition the
run uses (`minimize.py`; for example each seed state is merged with a state of another
routine). `M44.lean` is generated by `gen_reduced_lean.py`: it gives the merged table
`delta2`, a map `phi` from design states to merged states, and a check `compat` (one case per
state and symbol, closed by computation) that `delta2 (phi q) b` does what `delta q b` does
wherever the latter is defined (`Compat`). The generic lemma `halts_iff_of_sim`
(`Core/Basic.lean`, via `sim_run`) then shows the merged machine follows the design's run
step for step. It needs one extra fact, because the merged machine might in principle not
halt where the design halts: when the design halts it does so in `halt`, and `phi halt =
halt2` has no transition. `haltAt_of_fails` provides exactly this.

## What the proof does not cover

* It says nothing about whether Legendre's conjecture is true — that is the open problem.
  If it is true, the machine runs forever, and the proof shows exactly that.
* It says nothing about running time. Trial division by every `d < m` with unary
  arithmetic is slow; nothing in the proof depends on efficiency.
* The Lean theorem is about `delta2` as written in `M44.lean`. That `M44.lean`,
  `machines/legendre_44.txt`, the bbchallenge standard-text line in `README.md` and the
  annotated listing are the same machine rests on the generator scripts
  (`gen_reduced_lean.py`, `../tools/tm.py`, `annotate.py`), not on Lean.
