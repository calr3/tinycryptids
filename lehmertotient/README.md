# A Turing machine for Lehmer's totient problem

**Current best: `machines/lehmertotient_67.txt`, a 67-state, 2-symbol Turing machine**
(named-state format, see `../tools/tm.py`). Started on a blank tape, it **halts iff Lehmer's
totient problem has a counterexample**, i.e. iff some composite `n` has `φ(n) ∣ n − 1`. Lean
proves this (`TM.LehmerTotient.M67.halts_iff`):

    Halts M67.delta2 M67.start2 ↔ ∃ n, 2 ≤ n ∧ ¬ Prime n ∧ totient n ∣ n - 1

with `Prime` and `totient` from `../lean/TinyCryptids/Defs.lean`. `RECORDS.md` lists the machines, and
`PROOF.md` walks through the proof in plain words.

The 67-state machine is obtained in two stages:

1. `lehmertotient.txt` is the readable **106-state design**, generated by `build.py`. The Lean
   proof is written for this machine (`TM.LehmerTotient.halts_iff`).
2. `../tools/minimize.py` merges states of the design that never disagree on a transition the
   run uses (an exact SAT search; `kissat404`, `cadical195` and `maplechrono` all reach 67).
   `gen_reduced_lean.py` carries the theorem over, and `machines/lehmertotient_67_annotated.txt`
   is the same machine with each state named after its roles in the design.

## The search

    for n = 3, 4, 5, …:
        d := 1 + #{k ∈ [2, n − 1] : gcd(k, n − k) = 1}      (= φ(n))
        p := n − 1 − d
        if p ≥ 1 and d ∣ p: HALT

`φ(n)` is the number of `k ∈ [1, n − 1]` with `gcd(k, n − k) = gcd(k, n) = 1` (as in
`../carmichael`), and `k = 1` always counts. A prime has `φ(n) = n − 1` (`p = 0`), a composite
`φ(n) ≤ n − 2` (`p ≥ 1`); and `φ(n) ∣ n − 1` iff `φ(n) ∣ p`, since `n − 1 = p + φ(n)`. `n = 2`
is prime, so the search starts at 3.

## How it works

The tape, left to right:

    1 K 00 1 R 00 [D 00 P]

* **K/R** are `../carmichael`'s sweep blocks: `k` and `r` slots, `k + r = n`, each with a
  **hole** (a single 0) that ticks cyclically. The **walk** ticks both holes in lockstep; each
  time K's hole wraps, R's hole on its first slot means `gcd(k, r) = 1` and on its last slot
  means not (`0, k, 2k, …` mod `r` reaches 1 before 0 iff they are coprime). Both holes end
  on their first slots.
* **The pair** `D 00 P` is `../legendre`'s: `D = 1 0 1^d` (`d + 2` cells, its hole on cell 1)
  and `P` with `p + 2` cells; `d + p = n − 1` throughout round `n`.

One round:

* **count**: the walk tests `(k, n − k)` for `k = 2, …, n − 1`. After a coprime pair, a right
  parser finds D's hole and the pair's separator moves one cell right (`d + 1`, `p − 1`:
  `../legendre`'s shift); two left parsers find D's hole and then R's hole, back on R. If
  `r = 1` the round ends, else K/R's separator moves one cell right.
* **round end** (`(k, r) = (n − 1, 1)`, `d = φ(n)`): K/R becomes `(1, n)` (`../carmichael`'s
  reset), and a parser goes on to D's hole and the start of `../legendre`'s test. `p = 0`: `n`
  is prime, next `n`. Else one **mod walk** (`p` times: advance D's hole cyclically, then P's
  hole): D's hole back on cell 1 means `d ∣ p`, and the machine **halts**.
* **next n**: a cell after P (`d + p = n`); from P's end the separator and D's hole are filled,
  wherever the hole is, and `1 0 1 00` is written from D's left end (`d = 1`). Back on R as
  after a coprime pair; `r = n ≥ 2`, so K/R's separator moves: `(2, n − 1)`, the first test of
  round `n + 1`.

The seed writes round 3, `1 0 1 00 1 0 00 101 00 111` (K/R `(2, 1)`, the pair `(1, 1)`), right
to left, and starts the walk.

State budget of the 106-state design: seed 17, walk 24, next `k` 5, coprime 10, reset 12,
to the test 4, test start and mod walk 22, next `n` 12. The seed and the reset merge with
other states almost entirely; the walk and the parsers stay.
