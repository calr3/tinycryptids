# A Turing machine for Lemoine's conjecture

**Current best: `machines/lemoine_54.txt`, a 54-state, 2-symbol Turing machine**
(named-state format, see `../tools/tm.py`). Started on a blank tape, it **halts iff Lemoine's
conjecture is false**, i.e. iff some odd `n ≥ 7` is not `p + 2q` with `p`, `q` prime. Lean
proves this (`TM.Lemoine.M54.halts_iff`):

    Halts M54.delta2 M54.start2 ↔ ∃ n, 7 ≤ n ∧ n % 2 = 1 ∧ ∀ p q, Prime p → Prime q → p + 2 * q ≠ n

with `Prime` from `../lean/TinyCryptids/Defs.lean`. `RECORDS.md` lists the machines, and
`PROOF.md` walks through the proof in plain words.

The 54-state machine is obtained in two stages:

1. `lemoine.txt` is the readable **84-state design**, generated by `build.py`. The Lean proof
   is written for this machine (`TM.Lemoine.halts_iff`).
2. `../tools/minimize.py` merges states of the design that never disagree on a transition the
   run uses (an exact SAT search; `kissat404`, `cadical195` and `maplechrono` all reach 54).
   `gen_reduced_lean.py` carries the theorem over, and `machines/lemoine_54_annotated.txt` is
   the same machine with each state named after its roles in the design.

## The search

    for n = 7, 9, 11, …:
        for q = 2, 3, …:
            p := n − 2q
            if p = 1: HALT                    (no q is left: n is a counterexample)
            if p is prime and q is prime: next n

A representation `n = p + 2q` has `q ≥ 2` and `p ≥ 3` (n is odd, so `p = n − 2q` is odd), so
the loop over `q` with `p ≥ 3` covers all of them.

## How it works

Both primality tests are `../legendre`'s trial division. A **pair** `D 00 R` holds the number
`m = d + r` under test: D has `d + 2` cells and a **hole** (a single 0) at cell `c + 1`, a
cyclic counter; R has `r + 2` cells. The **mod walk** advances the D hole once per cell of R;
then `d ∣ r` (so `d ∣ m`) iff the hole is back at cell 1. If not, the **shift** moves the
separator one cell right (`d + 1`, `r − 1`). The test ends at a divisor `d < m` (composite) or
at `r = 0` (`d = m`, prime). A pair is **normalized** when `d = 2` (`D = 1011`); normalizing
fills the separator and rewrites it after cell 3, whatever the split was.

The tape, left to right:

    1 0 [Dp 00 Rp] 0^G [Dq 00 Rq] 0 1

* **P** holds `p = n − 2q`, **Q** holds `q`.
* The **sentinels** `1 0` and `0 1` tell the pairs apart: a composite test ends next to D's
  left end, where P has the left sentinel two cells away and Q the gap; a prime test ends at R's
  right end, where Q has the right sentinel two cells away and P the gap.
* The **gap** has `G = 2q` cells. Every `q += 1` erases the last two cells of Rp, so the gap
  records `2q`; it is even, so the 2-state hole parsers cross it like a separator.

One step of the search:

* **test p**: normalize P (coming from the end of Rp), then trial division. If R has a single
  cell, `p = 1`: the machine **halts** (the test start reads a 0 where R's second cell would be).
* **p composite → q += 1**: the right parser finds the Q hole and then the single 0 before the
  right sentinel; that 0 becomes a cell of Rq and the sentinel moves one cell right. Back over Q,
  across the gap, erase two cells of Rp (`p − 2`), test p.
* **p prime → test q**: on to the end of Rq the same way, normalize Q, trial division.
* **q composite → q += 1** as above.
* **q prime → next n**: erase Q and the right sentinel from the right, and fill the gap into Rp:
  P now holds `p + 2q = n` (with the two cells still to go, `n − 2 = (n + 2) − 4`). Write a new
  gap `00`, `Q = 1011 00 1` and the sentinel: these are the seed's last states. Then as after
  a composite: `q += 1` makes `q = 2`.

The seed writes `1 0 [1011 00 11111] 00 [1011 00 1] 0 1` and does `q += 1`: `n = 7`, `q = 2`.

State budget of the 84-state design: seed 24, trial division 30, which pair 5, `q += 1` and
`p −= 2` 9, normalize 7, to the end of Q 5, next `n` 4.
