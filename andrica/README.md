# A Turing machine for Andrica's conjecture

**Current best: `machines/andrica_51.txt`, a 51-state, 2-symbol Turing machine** (named-state
format, see `../tools/tm.py`). Started on a blank tape, it **halts iff Andrica's conjecture is
false**, i.e. iff some consecutive primes `p < q` have `√q − √p ≥ 1`, or in integers
`4p ≤ (q − p − 1)²`. Lean proves this (`TM.Andrica.M51.halts_iff`):

    Halts M51.delta2 M51.start2 ↔ ∃ p q, Prime p ∧ Prime q ∧ p < q ∧
        (∀ r, p < r → r < q → ¬ Prime r) ∧ 4 * p ≤ (q - p - 1) ^ 2

with `Prime` from `../lean/TinyCryptids/Defs.lean`. `RECORDS.md` lists the machines, and
`PROOF.md` walks through the proof in plain words.

The 51-state machine is obtained in two stages:

1. `andrica.txt` is the readable **88-state design**, generated by `build.py`. The Lean proof is
   written for this machine (`TM.Andrica.halts_iff`).
2. `../tools/minimize.py` merges states of the design that never disagree on a transition the
   run uses (an exact SAT search; `kissat404`, `cadical195` and `maplechrono` all reach 51).
   `gen_reduced_lean.py` carries the theorem over, and `machines/andrica_51_annotated.txt` is
   the same machine with each state named after its roles in the design.

## The search

`√q − √p ≥ 1` iff `q − p − 1 ≥ 2√p` iff `(q − p − 1)² ≥ 4p` (`q − p − 1 ≥ 0`). Let `t(m)` be
the least `t` with `t² ≥ 4m` (`t(m) = ⌈2√m⌉`). Then `4p ≤ g²` iff `t(p) ≤ g`, so the conjecture
fails iff after some prime `p` the next `t(p)` numbers are all composite:

    c := undefined
    for m = 2, 3, 4, …:
        if m is prime: c := t(m)
        else if c = 1: HALT          (m = p + t(p), and p + 1, …, m are composite)
        else c := c − 1

`t(m)` is kept on the tape: `t(m) = t` for `⌊(t − 1)²/4⌋ < m ≤ ⌊t²/4⌋`, that is for `⌊t/2⌋`
consecutive numbers, so a hole that moves two cells per number through a block of `t + 1`
cells leaves it exactly when `t` must grow.

## How it works

The tape, left to right:

    H 00 U 00 T 00 D 00 R

* **H** (the phase block) has `t + 1` cells, `t = t(m)`, and a **hole** (a single 0) at cell
  `2j − 1` when `m` is the `j`-th number with `t(m) = t`.
* **U 00 T**: `|U| + |T| = t`, and `|T|` is the countdown. U may be empty (then four 0s in a
  row); T never is.
* **The pair** `D 00 R` is `../legendre`'s: `D = 1 0 1^d` (`d + 2` cells, a hole) and R with
  `r + 2` cells, `d + r = m`.

One round:

* **test**: `../legendre`'s trial division of `m` by `d = 2, 3, …` (a mod walk per divisor:
  `r` times advance D's hole cyclically, then R's hole; D's hole back on cell 1 means `d ∣ m`).
  It ends at a divisor (`m` composite) or at `r = 0` (`m` prime).
* **composite**: a 2-state scan left finds the U/T separator (the second `00`) and moves it
  one cell right (`|T| − 1`). If T is empty now, the machine **halts**.
* **prime**: a parser crosses D's hole, the same kind of scan finds the U/T separator, which
  is filled and written again at U's left end (`|U| = 0`, `|T| = t`).
* **phase**: a parser finds H's hole and moves it two cells right. If it would leave H, H's
  last cell joins the H/U separator, whose last cell becomes U's new cell 0 (`|U| + |T| = t + 1`
  with `|T|` unchanged), and two new cells on H's left hold the new hole at cell 1.
* **next m**: a parser finds D's hole; `D := 2` and R gets the rest plus one cell
  (`../legendre`'s rebuild).

The seed writes `m = 2`, `1011 00 00 111 00 1011 00 11` (H with `t = 3`, U empty, `|T| = 3`,
`d = 2`, `r = 0`), left to right; 2 is prime.

State budget of the 88-state design: seed 21, test 30, composite 5, prime 9, phase 13, next
`m` 10. After merging every seed state is also a step of another routine.

An earlier version kept the countdown as a hole in T (`t + 2` cells) that moved one cell per
composite; finding that hole on the way back cost a parser, and the design had 90 states and
merged to 54.
