# A beeping Turing machine for amicable numbers

**Current best: `machines/amicable_55.txt`, a 55-state, 2-symbol beeping Turing machine**
(named-state format, as in `../oddperfect`). Started on a blank tape, it never halts, and it
takes its **beep transition** (state `H5` reading 0) exactly once for every `x` with
`s(x) > x` and `s(s(x)) = x`, where `s(x)` is the sum of the proper divisors of `x`.
These `x` are the smaller numbers of the amicable pairs: 220, 1184, 2620, 5020, ...
So it **quasihalts** (beeps only finitely often) **iff there are only finitely many amicable
numbers**. Lean proves this (`TM.Amicable.M55.quasihalts_iff`):

    QuasiHalts M55.delta2 St2.H5 false M55.start2 ↔ ¬ InfinitelyManyAmicable

with, in `../lean/TinyCryptids/Defs.lean`,

    def Amicable (n : Nat) : Prop := properDivSum n ≠ n ∧ properDivSum (properDivSum n) = n
    def InfinitelyManyAmicable : Prop := ∀ N, ∃ n, N ≤ n ∧ Amicable n

`properDivSum n` is the sum of the divisors `d < n` of `n` (the same definition as
`../oddperfect`). Whether there are infinitely many amicable numbers is open, and the
statement is Π₂, so it suits a beeping machine (Beeping Busy Beaver, BBB(55); BBBi(102)).
The machine beeps only for the smaller number of each pair. `inf_iff` (`Spec.lean`) shows
that infinitely many amicable numbers means infinitely many smaller numbers: if the partner
`m` of a large amicable `n > m` were below `N`, then `n = s(m) ≤ m² < N²`.

The 55-state machine is obtained in two stages, as for the other machines here:

1. `amicable.txt` is the readable **69-state design**, generated by `build.py`. The Lean
   proof is written for it (`TM.Amicable.quasihalts_iff`).
2. An exact SAT merge (`../tools/minimize_clique.py amicable.txt out 600 cadical195 H5:0`)
   gives 55 states. The clique bound is also 55, so 55 is optimal for this design.
   `gen_reduced_lean.py` carries the theorem over. `machines/amicable_55_annotated.txt`
   names each merged state after its roles in the design and comments every transition.

## How it works

Blocks of 1s are separated by `00`. A *hole* is a single 0 inside a block.

**The scan of a block** of `x + 4` cells is `../oddperfect`'s divisor loop, with its mod
walk and shift unchanged. The block is cut into `D 00 R` with `x = d + r + 1`. For
`d = 1 … x − 1`, a mod walk tests `d | x`. If it holds, the **add** walks D's hole down D,
and each step adds one unit to the **accumulator** to the left. A unit fills the
accumulator's hole (the third 0 left of D) and makes the next cell to its left the new
hole. If that cell is blank, the accumulator grows by one cell (`ACC 0 b → ACC 0 (b+1)`).
If it is one of the accumulator's own cells (a *preload*), the hole moves into it instead
(`ACC a b → ACC (a−1) (b+1)`). After the scan the accumulator holds `s(x)` more units, and
the block is `1^x 0000`.

**The same add routine copies a block.** Started with D = N, it adds N's length to the
accumulator. Its two uses as a copy end in different free transitions of the shift: `f3`
reads a marker, or `f4` reads a blank.

**One round, for `x = 1, 2, 3, …`** (it starts at `CS k`: `N = 1^k`, `x = k + 1`):

1. N gets four new cells and a marker two cells further on. N is copied (`x + 3` units)
   into a fresh block P on its left, and N gets one more cell, so N has `x + 4` cells.
   Erasing P's last cell turns P into a preload of `x + 1` cells. C1 and C2 cut N, and the
   scan of N runs (**pass 1**).
2. P's hole has reached its far end iff `s(x) ≥ x + 1`. If not, everything left of N is
   erased and the next round starts. If so, P has `s(x)` cells. Three more cells plus the
   filled hole make `m + 4` cells, with `m = s(x)`.
3. **Pass 2** scans that block, `m`, with a fresh accumulator A, which ends with `s(m)`
   cells. Then the block's zeros are filled and N is copied (`x` units) into the boundary
   between A and the block. The first unit fills the separator, and the others move the
   hole into A. Exactly one cell of A is left beyond the hole iff `s(m) = x`: **beep**.
4. Everything left of N is erased (N is `1^x` again) and the next round starts.

The first beep is at `x = 220` (step 644,401,737), with `m = 284`.

## Files and checks

* `build.py` generates the design (`python3 build.py amicable.txt`).
* `test_e2e.py [merged.txt]` compares the tape at every scan start (all `x ≤ 120`, both
  passes) with a model, checks that the first beep is at `x = 220` with no beep before it,
  checks the same for a merged machine, and checks that the design runs `10^8` steps.
* `ref.py`: `s(n)`. `psim.py`: a small Python stepper for debugging, with traces.
* `gen_lean.py` writes `../lean/TinyCryptids/Amicable/Machine.lean` (the design, with
  `deltaNB`, which has no beep). `gen_reduced_lean.py machines/amicable_55.txt M55` writes
  `M55.lean`, and `annotate.py` writes the readable listing.
* The proof is in `../lean/TinyCryptids/Amicable/` (`PROOF.md` gives a tour).
