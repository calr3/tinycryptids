# A Turing machine for the Feit–Thompson conjecture

**Current best: `machines/feitthompson_106.txt`, a 106-state, 2-symbol Turing machine**
(named-state format, as in `../fermat`). Started on a blank tape, it **halts iff the
Feit–Thompson conjecture is false**: iff there are distinct primes `p`, `q` with
`(q^p − 1)/(q − 1)` dividing `(p^q − 1)/(p − 1)`. Lean proves this
(`TM.FeitThompson.M106.halts_iff`):

    Halts M106.delta2 M106.start2 ↔ ∃ p q, Prime p ∧ Prime q ∧ p ≠ q ∧ rep p q ∣ rep q p

with `Prime` and `rep b n = 1 + b + … + b^(n−1)` from `../lean/TinyCryptids/Defs.lean`.
`RECORDS.md` lists every machine with its state count and Lean theorem. `PROOF.md` walks
through the proof in plain words.

The 106-state machine is obtained in two stages:

1. `feitthompson.txt` is the readable **149-state design**, generated by `build.py`.
   The Lean proof is written for this machine (`TM.FeitThompson.halts_iff`).
2. `minimize.py` merges states of the design that never disagree on a transition the run
   uses (an exact SAT search; 106 found, 105 not decided). `gen_reduced_lean.py` carries the
   theorem over. `machines/feitthompson_106_annotated.txt` is the same machine with each
   state named after its roles in the design, every transition commented.

## The search

For `1 ≤ p < q`, `rep q p < rep p q` (`rep_lt` in `../lean/TinyCryptids/FeitThompson/Arith.lean`),
so in a counterexample `rep p q ∣ rep q p` the prime `p` is the larger one. The machine
tests, for every prime `m = 3, 5, 7, …` and every prime `p < m`, whether
`rep m p ∣ rep p m` (`ft_iff`). Primality of `m` is decided by trial division by the
primes found so far, which the tape keeps as a list.

## How it works

A number `v` is a block of `v + 2` ones; its cells `1 … v` are the positions of a
**cyclic hole** (a single 0) that advances one cell right and wraps from cell `v` to cell 1.
Tape layout:

    L 00 P0 00 P1 00 … 00 Pk 00 M [00 A [00 B]]

* **L**, **M** hold the candidate `m`, each with a hole (at cell 1 at rest).
* **P0** = `111` holds 1; **P1 < … < Pk** are the primes below `m`. They are full except
  the **marker** (a hole at cell 1) of the block being visited.

**CYC(counter, cycled)**, the one divisibility test: the cycled block's hole goes round once
(`v` steps); before each step the counter's hole advances. It is back at cell 1 iff the
counter divides `v`.

Candidate `m`:

* **Trial pass**, left to right: `CYC(Pi, L)` for `i = 1 … k`. If `Pi ∣ m`, `m` is
  composite: `M += 1` (a cell on its right), `L += 1` (a cell on its left), the marker
  goes back to P1. Otherwise the marker moves right; reaching M (its cell 1 is a hole), `m`
  is prime.
* **Pair pass**, right to left, for `p = Pk … P1`: two **Horner** runs push
  `A = rep p m` and `B = rep m p` right of M, then `CYC(B, A)`: if `B ∣ A` the machine
  **halts**; otherwise A and B are erased and the marker moves one block left.
* **P0 step**: with P0 marked, the first Horner run writes `rep 1 m = m`: this copy becomes
  the next M while the old M (the prime `m`) joins the list. Then, as for a composite,
  `M += 1`, `L += 1`, and the trial pass of `m + 1` starts.

**Horner** pushes `R = 101` (it holds 1) and finds three holes going left: one it skips, the
base `b`, the exponent `e`. Each step of the exponent hole is a round `R := b·R + 1`: as
the base hole goes round, `b − 1` copies of R are appended after a `00`; then the `00` is
filled and one cell erased. After `e − 1` rounds `R = rep b e`. The first run skips M,
with base Pi and exponent L (`rep p m`); the second skips A, with base M and exponent Pi
(`rep m p`). Which run just ended is read off the blocks right of the exponent.

The seed writes the tape of `m = 2` (no primes, the marker on P0) and starts its P0 step,
which gives `m = 3` with the list `2`.

State budget of the 149-state design: seed 15, CYC 30 (with the parsers that decide what
follows), next candidate 13, retreat and push 10, Horner 52, after Horner 13, cleanup 11,
P0 step 5.

## Files and checks

* `build.py` generates the design (`python3 build.py feitthompson.txt`).
  `build(variant=1)` makes the test `B ∣ A − 1`, which halts at the pair `(2, 5)`.
* Shared tools in `../tools/`: `tm.py` parses the format and converts it to bbchallenge
  standard text (`python3 ../tools/tm.py machines/feitthompson_106.txt`); `sim.c` is a fast
  simulator; `same_run.py A B k` checks that two machines have identical tapes after
  10^3 .. 10^k steps; `minimize.py` (exact SAT) and `greedy_merge.py` merge states.
* `ref.py`: the pairs `(p, m)` in the order the machine tests them.
* `test_routines.py`: routines on hand-placed tapes: the trial pass for `m = 3 … 59` (prime
  or composite, the right block divides), Horner's `rep b e` and the pair test values, the
  transitions composite → next candidate, prime → pair pass, P0 step → next candidate.
* `test_e2e.py`: each pair the real machine tests (traced at `rt5`) matches `ref.py`, with
  the tape `L 00 P0 00 P1 … Pk 00 M`; the variant halts at `(2, 5)`; the real machine runs
  past 10⁸ steps.
* `gen_lean.py` writes `../lean/TinyCryptids/FeitThompson/Machine.lean` (the design);
  `gen_reduced_lean.py machines/feitthompson_106.txt M106` writes `M106.lean`;
  `annotate.py machines/feitthompson_106.txt machines/feitthompson_106_annotated.txt M106`:
  the readable listing.
* The proof: `../lean/TinyCryptids/FeitThompson/` (see `../lean/README.md`).
