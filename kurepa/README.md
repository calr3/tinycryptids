# A Turing machine for Kurepa's conjecture

**Current best: `machines/kurepa_38.txt`, a 38-state, 2-symbol Turing machine**
(named-state format, as in `../fermat`). Started on a blank tape, it **halts iff
Kurepa's conjecture is false**: iff some odd prime `p` divides the left factorial
`!p = 0! + 1! + … + (p − 1)!`. Lean proves this (`TM.Kurepa.M38.halts_iff`):

    Halts M38.delta2 M38.start2 ↔ ∃ p, Prime p ∧ 2 < p ∧ p ∣ leftFact p

with `Prime` and `leftFact` from `../lean/TinyCryptids/Defs.lean`. `RECORDS.md` lists every
machine with its state count and Lean theorem. `PROOF.md` walks through the proof in plain words.

The 38-state machine is obtained in two stages:

1. `kurepa.txt` is the readable **47-state design**, generated by `build.py`.
   The Lean proof is written for this machine (`TM.Kurepa.halts_iff`).
2. `minimize.py` merges states of the design that never disagree on a transition
   the run uses (an exact SAT search: 38 states, and 37 is unsatisfiable).
   `gen_reduced_lean.py` carries the theorem over. `machines/kurepa_38_annotated.txt`
   is the same machine with each state named after its roles in the design, every
   transition commented.

## The search

The machine tests **every** `n ≥ 3` for `n ∣ !n`, not only primes. That is the same
condition (`kurepa_iff` in `../lean/TinyCryptids/Kurepa/Spec.lean`): a prime `q ≤ n` divides
`k!` for every `k ≥ q`, so `!n ≡ !q (mod q)`; and `!n ≡ 2 (mod 4)` for `n ≥ 4`. So if
`n ∣ !n`, then `4 ∤ n`, `n` has an odd prime factor `p`, and `p ∣ !p`. No primality test is
needed.

Round `n` keeps `!n` and `n!` in unary and moves on with `!(n+1) = !n + n!` and
`(n+1)! = (n+1)·n!`.

## How it works

Tape layout:

    N 00 L m1 F m2 Q          (m1, m2: markers, single 0s inside one block)

* **N** has cells `0 .. m` (`m = n` in the test, `n + 1` in the multiplication) and one
  **hole** (a single 0) at a cell `1 .. m`.
* **L** has `!n + n + 1` cells, **F** has `n!` cells, **Q** collects the copies of F.

Round `n`:

* **Test.** A hole walks through L from its right end to its left end. For each cell it
  passes, the N hole steps one cell right, wrapping from cell `n` to cell 1. It starts at
  cell `n` and makes `|L| − 1 = !n + n` steps, so it is back at cell `n` iff `n ∣ !n`:
  then the machine **halts**.
* **Grow.** Otherwise the N hole is filled, N gets one more cell on its left, and the
  hole goes to cell 1.
* **Multiply.** A copy cursor walks F; for each cell a 1 is appended to Q. After each
  pass the N hole steps right; after `n + 1` passes it falls off the end of N (it is put
  back at the last cell). Now `Q = (n+1)!`.
* **Merge.** The marker m1 is filled: `L := L + 1 + F` (the extra cell is why `|L|` carries
  `+ n`). Q becomes the new F and m2 the new m1. The test of `n + 1` starts at the right
  end of L.

The seed writes round 2 right to left (`F = 11`, m1, `L = 11111`, `00`, `N = 111`) as it is
after its test, and enters the growth of N: the test of `n = 2` (which would halt, since
`2 ∣ !2`) is skipped.

State budget of the 47-state design: seed 13, test 13, growth 3, multiplication 13, merge 5.
After merging, the half-used states (those that only ever read 0 or only ever read 1) pair up;
the 37-state search is unsatisfiable.

## Files and checks

* `build.py` generates the design (`python3 build.py kurepa.txt`).
* Shared tools in `../tools/`: `tm.py` parses the format and converts it to
  bbchallenge standard text (`python3 ../tools/tm.py machines/kurepa_38.txt`); `sim.c` is a fast
  simulator (`gcc -O2 -o ../tools/sim ../tools/sim.c`); `same_run.py A B k`
  checks that two machines have identical tapes after 10^3 .. 10^k steps;
  `minimize.py` (exact SAT) and `greedy_merge.py` merge states; `leangen.py`
  writes the generated Lean files.
* `test_e2e.py`: at the end of each test up to `n = 8` the tape holds `|N| = n + 1`,
  `|L| = !n + n + 1`, `|F| = n!` and the N hole at the cell predicted by `!n + n mod n`. Test
  variants halt: from `n = 1` (the seed of round 1) at `n = 2`, and with L one cell longer
  (testing `n ∣ !n + 1`) at `n = 5` (`!5 + 1 = 35`). The real machine runs past 10⁹ steps.
* `gen_lean.py` writes `../lean/TinyCryptids/Kurepa/Machine.lean` (the design);
  `gen_reduced_lean.py machines/kurepa_38.txt M38` writes `M38.lean`;
  `annotate.py machines/kurepa_38.txt machines/kurepa_38_annotated.txt M38`: the readable listing.
* The proof: `../lean/TinyCryptids/Kurepa/` (see `../lean/README.md`).
