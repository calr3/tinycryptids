# The proof, in plain words

This is a guided tour of the Lean proof that the 38-state machine `machines/kurepa_38.txt`
halts if and only if Kurepa's conjecture is false: some odd prime `p` divides the left
factorial `!p = 0! + 1! + … + (p − 1)!`. The hand-written proof is about 560 lines in
`../lean/TinyCryptids/Kurepa/` (`Spec.lean`, `Tac.lean`, `Round.lean`, `Main.lean`); the machine
tables `Machine.lean` and `M38.lean` are generated. Each step below names the lemma that
carries it.

## What is proved

```lean
theorem TM.Kurepa.halts_iff :
    Halts delta start ↔ ∃ p, Prime p ∧ 2 < p ∧ p ∣ leftFact p

theorem TM.Kurepa.M38.halts_iff :
    Halts M38.delta2 M38.start2 ↔ ∃ p, Prime p ∧ 2 < p ∧ p ∣ leftFact p
```

* `leftFact 0 = 0`, `leftFact (n + 1) = leftFact n + fact n`, so `leftFact n = !n`; `fact` is
  the factorial and `Prime p` is "`2 ≤ p` and no `d` with `2 ≤ d < p` divides `p`"
  (`TinyCryptids`, `../lean/TinyCryptids/Defs.lean`).
* `delta` is the 47-state design `kurepa.txt` (generated by `build.py`, transcribed by
  `gen_lean.py` into `Machine.lean`), `start` is its first state on a blank tape. `delta2` is
  the 38-state machine `machines/kurepa_38.txt` (`M38.lean`), `start2` likewise.
* `Halts δ c` means: started in configuration `c`, the machine reaches a configuration with
  no transition (`../lean/TinyCryptids/Core/Basic.lean`, the model shared by every machine in the
  repository: 2 symbols, a two-way infinite tape, the head always moves).

To trust the result you need to trust the Lean kernel, the definitions above, and the listing
of the machine. Both theorems depend only on Lean's standard axioms `propext`,
`Classical.choice` and `Quot.sound` (`../lean/Check.lean` prints this).

The proof has four parts: arithmetic (`Spec.lean`), the machine's routines on the tape
(`Round.lean`, using the step tactics of `Tac.lean`), the main theorem for the design
(`Main.lean`), and the transfer to the 38-state machine (`M38.lean`).

## The idea

The machine runs **rounds** `n = 3, 4, 5, …`, keeping `!n` and `n!` on the tape in unary:

    for n = 3, 4, 5, …:
      if n ∣ !n: HALT
      !(n+1) := !n + n!
      (n+1)! := (n+1) · n!                    (n+1 copies of n!)

It tests every `n`, not only primes: the statement "some `n ≥ 3` divides `!n`" is equivalent to
Kurepa's (Part 1), and needs no primality test. **The test** walks a hole through the block
holding `!n` while a second hole steps cyclically through a block of `n` positions; the
second hole is back where it started iff the number of steps is a multiple of `n`.
**The factorial** is built by copying, and the **left factorial** by joining the factorial's
block to it: the two blocks sit in one block of 1s, separated by a single 0 (a *marker*), and
filling the marker adds the factorial to the left factorial.

## Part 1: arithmetic (`Spec.lean`)

**Lemma 1 (`fact_pos`, `dvd_fact`).** `n! ≥ 1`, and `q ∣ k!` whenever `1 ≤ q ≤ k`.

**Lemma 2 (`leftFact_mod`).** For `q ≥ 1`: `!(q + k) mod q = !q mod q`. *Proof:* induction on
`k`; `!(q + k + 1) = !(q + k) + (q + k)!`, and `q` divides the added factorial (Lemma 1).

**Lemma 3 (`exists_prime_dvd`).** Every `d ≥ 2` has a prime divisor (strong induction: if `d`
is not prime it has a divisor `2 ≤ e < d`).

**Lemma 4 (`kurepa_iff`).** Some `n ≥ 3` divides `!n` iff some odd prime `p` divides `!p`.
*Proof:* (←) take `n = p`. (→) First, `4 ∤ n`: otherwise `n ≥ 4` and Lemma 2 with `q = 4` gives
`!n ≡ !4 = 10 ≡ 2 (mod 4)`, while `4 ∣ n ∣ !n`. So `n` is odd, or `n = 2k` with `k` odd and
`k ≥ 3`; either way `n` has an odd divisor `d ≥ 3`, and by Lemma 3 a prime `p ∣ d`, which is
odd, so `p > 2`. Then `p ∣ n ∣ !n`, `p ≤ n`, and by Lemma 2 `!p ≡ !n ≡ 0 (mod p)`.

## Part 2: the machine on the tape (`Round.lean`)

**The tape.**

    N 00 L m1 F m2 Q

* `N`: cells `0 … m`, a hole (a single 0) at a cell `c` with `1 ≤ c ≤ m`. Seen from its right
  end it is `NL m c = ones (m − c) (0 ::: ones c blank)`. In the test of round `n`, `m = n`; in
  its multiplication `m = n + 1`.
* `L`: `lam` cells (`lam = !n + n + 1`); `F`: `K` cells (`K = n!`), right of the marker `m1`;
  `Q`: `q` cells, right of the marker `m2` (only during the multiplication).

In Lean, a configuration is a state with the tape left of the head and the tape from the head
on, each as a stream of cells; `ones k s` is `k` cells of 1 followed by `s`. Every lemma below is
proved by stepping the machine one transition at a time (the tactics `gR`, `gL`, `gL0` of
`Tac.lean`, each closed by computation on `delta`) and jumping over runs of 1s with `scanR`,
`scanL` (`Core/Lemmas.lean`). The "parsers" (two states that run over 1s, skip a `00` and stop
past a single 0) are stepped the same way.

### The test

The checkpoint `TP m c lam K j` is: state `p2` on cell `j` of `L` (all of `L` is 1s), the `N`
hole at `c`. `p2` makes cell `j` the hole of `L`, the parser `PN` finds the `N` hole, `s1`–`s5`
move it one cell right (from cell `m` it wraps to cell 1: `s3` runs left to the blank, `s5`
writes the hole at cell 1), the parser `PT` finds the `L` hole again and `p1` fills it; `p2` is
now on cell `j − 1`. With `nx m c` the next position (`c + 1` if `c < m`, else 1):

| situation | result | lemma |
|---|---|---|
| one unit, `c < m` | `N` hole at `c + 1` | `unit_step` |
| one unit, `c = m` | `N` hole at 1 | `unit_wrap` |
| `j ≥ 1` | `TP m (nx m c) lam K (j − 1)` | `test_step` |
| `j = 0` | `p2` on the separator left of `L`: `TE m (nx m c) lam K` | `test_last` |
| end, `c = m` | `k1`, `k2` read cell `m` of `N`: a 0, **the machine halts** | `te_halt` |
| end, `c < m` | `kk` fills the `N` hole, `gg` adds a cell to `N` on its left, `gh` puts the hole at cell 1: `PGc (m + 1) 1 lam K 0` | `te_grow` |

The unit lemmas are stated for any tape right of the hole (`unit_any`), so the last unit (hole
at cell 0 of `L`, next to the separator) is the same lemma as the others.

### The multiplication

`PGc m a lam K q`: the parser `PG` about to run right from the `N` hole at `a`. `X m a lam K b q`:
the copy cursor at `f_b`, the head on the marker `m2`, state `x1`.

| step | what the machine does | lemma |
|---|---|---|
| start of a copy | `PG` finds `m1` and writes the cursor at `f_0`; `x1` runs to `m2` | `pg_to_x` |
| cursor not at the last cell | `x2` appends a 1 to `Q`, `y0`, `y1` run back and fill the cursor, `y2` writes the next one | `copy_one` |
| cursor at the last cell | append, fill the cursor; `y2` reads `m2`: `z1` runs to `m1`, the parser `PC` finds the `N` hole | `copy_last` |
| `N` hole not at the last cell | `c1`, `c2` move it one cell right: next copy, `PGc m (a+1) lam K (q+1)` | `c_next` |
| `N` hole at the last cell | `c2` reads the separator, `c3` puts the hole back at cell `m`: `PMc m lam K (q+1)` | `c_fall` |
| merge | the parser `PM` finds `m1`, `m1` fills it, `m2` runs to the marker `m2`, `m3` steps left: `TP m m (lam + 1 + K) q (lam + K − 1)` | `merge` |

After the merge, `L` is `lam + 1 + K` cells long (old `L`, the filled marker, old `F`), `Q` is
the new `F`, the old `m2` the new `m1`, and the test of the next round starts with `p2` on the
next-to-last cell of `L` and the `N` hole at its last cell.

## Part 3: the main theorem for the design (`Main.lean`)

**Lemma 5 (`test_run`).** From `TP m c lam K j` the machine reaches
`TE m (nxs m c (j + 1)) lam K`, where `nxs m c u` is `nx` applied `u` times: induction on `j`
with `test_step`, then `test_last`.

**Lemma 6 (`nxs_m`, `nxs_m_eq`).** From cell `m`, `nxs m m u = (u + m − 1) mod m + 1`, so the
hole is back at `m` after `u` steps iff `m ∣ u`.

**Lemma 7 (`copies`, `multiply`).** From `PGc m 1 lam K 0` the machine reaches
`PMc m lam K (m · K)`: induction on the remaining work `(m − a) · K + (K − 1 − b)`, with
`copy_one`, or `copy_last` followed by `c_next` and `pg_to_x`, or at the very end `c_fall`.

Let `lam n = !n + n + 1` and `RS n = TP n n (lam n) (n!) (lam n − 2)`: the start of the test of
round `n`.

**Lemma 8 (a round, `round`).** For `n ≥ 2`: if `n ∣ !n`, the machine halts from `RS n`;
otherwise it strictly reaches `RS (n + 1)`. *Proof:* Lemma 5 with `j = lam n − 2`, so
`lam n − 1 = !n + n` steps; by Lemma 6 the hole is at `n` iff `n ∣ !n + n` iff `n ∣ !n`. If so,
`te_halt`. If not, `te_grow`, Lemma 7 with `m = n + 1`, and `merge` reach
`TP (n+1) (n+1) (lam n + 1 + n!) ((n+1) · n!) (lam n + n! − 1)`, which is `RS (n + 1)` because
`!(n+1) = !n + n!` and `(n+1)! = (n+1) · n!`. "Strictly" (`Reach1`) because the run passes
through `PGc`, whose state differs from `p2` (`reach1_of`).

**The seed** (`seed_reach`, `start_reach`). Thirteen states write
`11 0 11111 00 111` from right to left (`F = 2!`, `m1`, `L` of `lam 2 = 5` cells, the
separator, three cells of `N`), and enter `gg` on the blank left of `N`: exactly as after a
test, `gg` and `gh` give `PGc 3 1 5 2 0`. Then `multiply` and `merge` give `RS 3`. Round 2's
test, which would halt (`2 ∣ !2`), is never run.

**Halting gives a counterexample.** Suppose the machine halts but no `n ≥ 3` divides `!n`.
Then every `RS n` with `n ≥ 3` strictly reaches `RS (n + 1)`, so the machine never halts from
`RS 3` (`not_halts_of_progress`); since `start` reaches `RS 3` and the machine is deterministic
(`halts_det`), it does not halt from `start` — contradiction.

**A counterexample makes it halt** (`haltAt_of`). If `N ≥ 3` divides `!N`, then from `RS 3`
each round either halts or passes to the next, and round `N` halts (induction on `N − n`).
`HaltAt c` means: from `c` the machine reaches the explicit state `halt`.

With Lemma 4 this is `TM.Kurepa.halts_iff`, for the 47-state design `kurepa.txt`.

## Part 4: the 38-state machine (`M38.lean`)

`M38` is obtained from the design by merging states that never disagree on a transition the
run uses. `M38.lean` is generated by `gen_reduced_lean.py`: it gives the merged table `delta2`,
a map `phi` from design states to merged states, and a check `compat` (one case per
transition, closed by computation) that `delta2 (phi q) b` does what `delta q b` does wherever
the latter is defined. The generic lemma `halts_iff_of_sim` (`Core/Basic.lean`) then shows that
the merged machine follows the design's run step for step and halts exactly when it does; the
one extra fact it needs, that the design halts only in its explicit state `halt`, comes from
`haltAt_of`.

## What the proof does not cover

* Whether a counterexample exists: that is the open problem (computer searches have found
  none). If there is none, the machine runs forever, and the proof shows exactly that.
* The test variants of `build.py` (used in `test_e2e.py`) are checked by simulation only.
* The arithmetic is unary: round `n` takes more than `(n+1)!` steps, so any feasible run checks
  only small `n`. The proof is about halting, not running time.
* The bbchallenge standard-text line in `README.md` and the annotated listing
  `machines/kurepa_38_annotated.txt` are printed from the same machine file; `annotate.py`
  checks the listing is the same machine.
