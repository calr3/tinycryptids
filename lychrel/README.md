# A Turing machine for the 196 problem (Lychrel numbers)

**Current best: `machines/lychrel_95.txt`, a 95-state, 2-symbol Turing machine**
(named-state format, see `../tools/tm.py`). Started on a blank tape, it **halts iff
reverse-and-add from 196 reaches a palindrome**, i.e. iff 196 is not a Lychrel number.
Lean proves this (`TM.Lychrel.M95.halts_iff`):

    Halts M95.delta2 M95.start2 ↔
      ∃ k, rev10 (iterate (fun x => x + rev10 x) k 196) = iterate (fun x => x + rev10 x) k 196

`RECORDS.md` lists the machines, and `PROOF.md` walks through the proof in plain words.

The 95-state machine is obtained in two stages:

1. `lychrel.txt` is the readable **134-state design**, generated by `build.py`. The Lean proof
   is written for this machine (`TM.Lychrel.halts_iff`).
2. `../tools/minimize.py` merges states of the design that never disagree on a transition the
   run uses (an exact SAT search; `kissat404` and `cadical195`). `gen_reduced_lean.py` carries
   the theorem over, and `machines/lychrel_95_annotated.txt` is the same machine with each state
   named after its roles in the design.

## The search

    x := 196
    loop:
        T := x, A := 0
        while T > 0:  A := 10 A + T mod 10,  T := T div 10      (now A = rev10 x)
        if A = x: HALT
        x := x + A

The inner loop is exactly `revAux`, so the proof follows the definition of `rev10` step by step.

## How it works

All numbers are in unary. The tape, left to right (blocks of 1s; separators are runs of at
least two 0s; a hole is a single 0):

    D 00 X G T 00 A 00 Q 00 P

* **D** is 12 cells `d0 … d11` with one hole at `d(p+1)`: a counter `p` mod 10. `p += 1` moves the
  hole right, and from `d10` it wraps to `d1`; `p -= 1` moves it left, and wraps from `d1` to `d10`.
* **X** has `x + 3` cells, **T** `t + 3` (with a hole, the division's cursor), **A** `a + 1`.
  In the first iteration of a round T is X itself; later T is a block of its own after a gap G.
* **Q** and **P** are made at the right end of the tape by their first cell.

One iteration, `A := 10 A + T mod 10`, `T := T div 10`:

1. **Division.** With `p = 9` and T's hole at cell 1, repeat: `p += 1`; if `p` wrapped, append a
   cell to Q (or make Q with 3 cells); move T's hole one cell right — until the hole reaches T's
   last cell. That is `t + 1` steps, so Q ends with `t div 10 + 3` cells and `p = t mod 10`.
   T is then erased, unless it is X (two 0s and D on its left).
2. **Multiplication.** Repeat: append a cell to P (the first one makes P); `p -= 1`; when `p`
   wraps to 9, erase A's first cell, or stop if A has only one. P ends with
   `t mod 10 + 10 a + 1` cells, the code of the new A, and `p = 9` again.
3. A's last cell is erased: Q and P become T and A. If T has 3 cells (`t = 0`), A = rev10 x.

**Compare and add.** T is erased and a hole walks X from cell `x + 1` down to 1; for each position
one cell of A is moved to X's end. If A is down to its last cell while the hole is at cell 1,
then `a = x`: HALT. Otherwise the hole is filled (or, when the walk ends first, the rest of A is
moved), X has `x + a + 3` cells, A's last cell stays as the new `A = 0`, and X's hole goes to
cell 1: the next round starts with T = X.

**Seed.** The seed writes the tape of the multiplication for `T = 59`, `A = 1` with `x = 1`
(35 cells): the run computes `A = 195` and `x = 1 + 195 = 196`, and goes on from there.
