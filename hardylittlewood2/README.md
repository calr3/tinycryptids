# A Turing machine for the second Hardy–Littlewood conjecture

**Current best: `machines/hardylittlewood2_79.txt`, a 79-state, 2-symbol Turing machine**
(named-state format, see `../tools/tm.py`). Started on a blank tape, it **halts iff the second
Hardy–Littlewood conjecture is false**, i.e. iff `π(x) + π(y) < π(x + y)` for some `x, y ≥ 2`.
Lean proves this (`TM.HardyLittlewood2.M79.halts_iff`):

    Halts M79.delta2 M79.start2 ↔
      ∃ x y, 2 ≤ x ∧ 2 ≤ y ∧ primeCount x + primeCount y < primeCount (x + y)

where `primeCount x` is the number of primes `≤ x` and `Prime p := 2 ≤ p ∧ ∀ d, d < p → 2 ≤ d →
p % d ≠ 0` (`../lean/TinyCryptids/Defs.lean`). `RECORDS.md` lists the machines, and
`PROOF.md` walks through the proof in plain words.

The conjecture is widely believed to be false (it is incompatible with the prime k-tuples
conjecture), but any counterexample is far beyond reach: the machine is expected to run forever
in practice, and halts exactly when a counterexample exists.

The 79-state machine is obtained in two stages:

1. `hardylittlewood2.txt` is the readable **136-state design**, generated by `build.py`. The Lean
   proof is written for this machine (`TM.HardyLittlewood2.halts_iff`).
2. `../tools/minimize.py` merges states of the design that never disagree on a transition the
   run uses (an exact SAT search). `gen_reduced_lean.py` carries the theorem over, and
   `machines/hardylittlewood2_79_annotated.txt` is the same machine with each state named after
   its roles in the design.

## The reduction

Let `q₀ = 1, q₁ = 3, q₂ = 5, …` be 1 and the odd primes: for `x ≥ 2` they are counted by `π(x)`
(1 stands in for 2). Let `h_i = (q_i − q_{i−1})/2` be the half gaps (`h₁ = 1`).

* A counterexample `(x, y)` with `x + y = n` gives one with `x + y = m`, the largest prime
  `≤ n` (shrink the window `(y, n]` to `(y, m]`).
* At the prime `m = q_G`, with `y = q_j − 1`: `π(m) − π(y) = G + 1 − j`, so the counterexamples
  are exactly the `i` in `[1, G − 1]` with `q_i + q_{G−i} > m + 1`, i.e.

        h_G + h_{G−1} + … + h_{G+1−i}  <  h₁ + h₂ + … + h_i

  (the `i`-th prime counting down from `m` is closer to `m` than the `i`-th prime counting up
  from 1 is to 1).
* This is checked with one counter: `E := 0`; for `i = 1 … G−1`: `E += h_{G+1−i}`, then
  `E −= h_i`; a counterexample iff `E` would drop below 0.

No multiplication, no search over pairs: one primality test per odd number and one pass over the
gaps per prime.

## How it works

The tape, left to right (blocks of 1s, separators `0 0`; a gap block for `h` has `h + 2` cells):

    [E 0000] B' 00 A 00 C 00 D 00 R

* **B'** holds the gaps newest first, **A** the same gaps oldest first. A's first block `h₁ = 1`
  carries a hole at cell 1: the *parked* cursor, which marks where B' ends.
* **C** has `c + 2` cells, `c = (m − q)/2` for the candidate `m` and the last prime `q`: the next
  gap. It grows by one cell per candidate and becomes A's last block when `m` is prime.
* **D** and **R** do trial division of `m = d + r` from `d = 3` by the mod walk of
  `../legendre/` (as in `../sierpinski/`).
* **E** exists only during the test: `e + 1` cells at the far left, four 0s away from B'.

**Composite** `m`: C gets one more cell, D := 3 and R := `m + 2 − 3` cells (fill the D/R
separator, append 3 cells, go back to the D hole and write a fixed pattern three cells left of
it).

**Prime** `m` (the test): the *top* cursor (a hole) walks C and then A right to left
(`h_G, h_{G−1}, …`), the *bottom* cursor starts at the parked hole and walks B' right to left
(`h₁, h₂, …`). For each cell the machine goes home to E (left to the run of four 0s) and back:
a top cell adds a cell to E, a bottom cell removes one, and if only E's base cell is left the
machine **halts**. The top cursor is always the second hole from the left and the bottom cursor
the first, so the way back is one or two hole-finding parsers. When B' is used up, E has
`h_G = c` cells; two more close the gap and E becomes B''s new first block. The top cursor has
stopped on A's first block: parked again, and C stays as A's last block. Then a new C of one
cell, D := 3, R := `m + 2 − 3` (the D hole moved four cells right, so the composite pattern lands
after the new C; 7 cells appended).

The seed writes the tape at the prime 5 (B' = A = `[1]`, C = 1, D = `1 0 1⁵`, R = `11`) and enters
the test.

State budget of the 136-state design: seed 26, mod walk and shift 30, rebuilds 33, test start 8,
cursors 14, add trip 11, subtract trip 9, test end 5.
