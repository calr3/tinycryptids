# The proof, in plain words

This is a guided tour of the Lean proof that the 68-state machine `legendre.txt` (and the
45-state machine `machines/legendre_45.txt` obtained from it) halts if and only if Legendre's
conjecture is false. The proof is about 950 lines (not counting the generated machine tables) in `../lean/TinyCryptids/LegendreSieve/`, on top
of the shared machine model in `../lean/TinyCryptids/Core/`; each step below names the lemma that
carries it.

## What is proved

```lean
theorem TM.LegendreSieve.halts_iff :
    Halts delta start ↔ ∃ n, 1 ≤ n ∧ ∀ p, n ^ 2 < p → p < (n + 1) ^ 2 → ¬ TinyCryptids.Prime p

theorem TM.LegendreSieve.M45.halts_iff :
    Halts delta2 start2 ↔ ∃ n, 1 ≤ n ∧ ∀ p, n ^ 2 < p → p < (n + 1) ^ 2 → ¬ TinyCryptids.Prime p
```

* `TinyCryptids.Prime p` is `2 ≤ p ∧ ∀ d, d < p → 2 ≤ d → p % d ≠ 0`: no number from 2 to `p − 1`
  divides `p` (`../lean/TinyCryptids/Defs.lean`). This is the trial-division form; Part 5 explains
  how the proof switches to the divisor form.
* `delta`, `start` are the 68-state design (`Machine.lean`, generated by `gen_lean.py` from
  `legendre.txt`); `start` is state `seed0` on a blank tape. `delta2`, `start2` are the 45-state
  machine (`M45.lean`, generated by `gen_reduced_lean.py`). The Lean state types also have one
  explicit `halt` state (`halt2` in `M45`) with no transitions, not counted in the state number.
* `Halts δ c` means: started in configuration `c`, the machine reaches a configuration with
  no transition (`../lean/TinyCryptids/Core/Basic.lean`, the model shared by every machine in the
  repository: 2 symbols, a two-way infinite tape, the head always moves).
* So the right-hand side says: for some `n ≥ 1` no prime lies strictly between `n²` and
  `(n + 1)²` — a counterexample to Legendre's conjecture.

To trust the result you need to trust the Lean kernel, the definitions above, and the listing
of the machine. Nothing else: both theorems depend only on Lean's standard axioms `propext`,
`Classical.choice` and `Quot.sound` (`../lean/Check.lean` prints this). No Mathlib; every fact
about primes is proved from the definition.

## The idea

The machine is an **incremental sieve**. It visits `m = 1, 2, 3, …` in order and keeps, for
every prime `p ≤ m`, a block that knows `m mod p`. Going from `m` to `m + 1` it moves every
block's residue on by one; a block whose residue wraps to 0 has found a prime divisor of
`m + 1`. If no block wraps, `m + 1` is prime, and the machine makes a new block for it. A
second counter of the same shape, with period `2n + 1`, wraps exactly when `m + 1` is the next
square `(n + 1)²`; a one-cell flag `F` records whether a prime has appeared since `n²`. If the
square counter wraps while the flag is clear, the interval `(n², (n + 1)²)` contained no prime
and the machine halts. The proof follows a single **checkpoint invariant** `Inv m n f`:
`n ≥ 1`, `n² ≤ m < (n + 1)²`, and `f = true` iff some prime `p` has `n² < p ≤ m`. Each
increment either halts — exactly in the counterexample situation — or reaches the checkpoint
for `m + 1` with the invariant restored.

## Part 1: the tape (`Tape.lean`, `Sweep.lean`, `Math.lean`)

A **block** `blk a b` is: a guard 1, `a` ones, one 0 (the *hole*), `b` ones, a guard 1. Its
*region* (between the guards) has `a + b + 1` cells and the hole is at region index `a`.
`blkR a b` is the same block as seen when it lies left of the head (read right to left).

At checkpoint `m` the tape is the list `CW m n f`:

    M 00 P_k 00 … 00 P_1 00 0 S 0 F

| piece | contents | Lean |
|---|---|---|
| `M` | `m + 2` ones: a plain counter, the only block without a hole | `List.replicate (m+2) true` |
| `P_i` | one block per prime `p ≤ m`, largest first, each followed by `00`; the block of `p` is `blk (p − 1 − m mod p) (m mod p)` | `pb m p`, `blocks m`, `pzList` |
| `0` | one more 0: with the `00` before it this is the only run of exactly three 0s | |
| `S` | the square counter, `blk (2n − (m − n²)) (m − n²)`: region `2n + 1`, hole index `2n − (m − n²)` | |
| `0 F` | a 0, then the flag cell `F = f` | |

Everything else is blank. The left end of the tape is the only run of four or more 0s. The
checkpoint configuration `chk m n f` (`chkW` in `Home.lean`) has the head in state `hg5` three
cells left of `M`'s first 1.

* `primesDesc m` is the list of the primes `≤ m`, largest first; `mem_primesDesc`:
  `p ∈ primesDesc m ↔ PrimeDvd p ∧ p ≤ m`.
* `stp` is what the sweep does to one block, as a pair (hole index, cells after the hole):
  `(a + 1, b) ↦ (a, b + 1)` (hole one cell left) and `(0, b) ↦ (b, 0)` (wrap to the last
  index). `wraps l` says whether some block of `l` has hole index 0.

**Lemma 1 (a sieve step on the residues, `stp_pb`, `blocks_map`).** For a prime `p`,
`stp (pb m p) = pb (m + 1) p`: moving the hole left by one cell, wrapping from index 0 to
`p − 1`, is exactly `m mod p ↦ (m + 1) mod p`. So `(blocks m).map stp` lists the blocks of the
same primes at `m + 1` (`map_stp`).

**Lemma 2 (who wraps, `wraps_pb`, `wraps_blocks`).** A block of `p` has hole index 0 iff
`p ∣ m + 1`. Hence for `m ≥ 1`: `wraps (blocks m) = true ↔ ¬ PrimeDvd (m + 1)`. The second
step is `not_prime_iff`: `m + 1` is composite iff some prime `p ≤ m` divides it, which needs
`exists_prime_dvd` (every `n ≥ 2` has a prime divisor; strong induction, taking a proper
divisor when `n` is not prime).

**Lemma 3 (the new block list, `blocks_succ_prime`, `blocks_succ_comp`).** If `m + 1` is prime,
`blocks (m + 1) = (m, 0) :: (blocks m).map stp` — the new prime `m + 1` comes first, with its
hole at the last index `m` (residue 0). Otherwise `blocks (m + 1) = (blocks m).map stp`.

**Lemma 4 (squares, `sq_succ`, `sq_not_prime`, `s_arith`).** `(n + 1)² = n² + 2n + 1`, so the
S hole index `2n − (m − n²)` is 0 exactly when `m + 1 = (n + 1)²`; and `(n + 1)²` is never
prime for `n ≥ 1`.

## Part 2: one increment, routine by routine

### Grow and sweep (`Sweep.lean`, `sweep_all` in `Tape.lean`)

From the checkpoint the head steps right twice, writes a 1 on the cell just left of `M` (so `M`
now has `m + 3` ones), and starts the sweep in **prime mode** (states `p1 p2 p3`). The sweep is
a parser in two copies, prime mode `p…` and **composite mode** `q…` (`S1`, `S2`, `S3` pick the
copy by a Boolean). It crosses ones, counts 0s (one 0: a hole was passed; two: a separator;
three: the end of the P zone) and handles each hole:

| hole index | what happens | lemma |
|---|---|---|
| `a + 1 ≥ 1` | fill the hole, look two cells left (a 1), make the new hole one cell left; mode unchanged | `blk_move` |
| `0` | the cell two left of the hole is the separator 0: run right to the guard (`W2`, `W3`), put the hole on the last region cell (`W4`), continue in composite mode | `blk_wrap` |

**Lemma 5 (the sweep, `zone`).** By induction over the block list: from mode `c`, crossing
`pz l` reaches mode `c || wraps l` with the blocks `l.map stp` behind the head.
`sweep_all` assembles grow + sweep from the checkpoint: the sweep ends on the three 0s before
S in state `S3 (wraps (blocks m))`, i.e. in composite mode iff `m + 1` is composite
(Lemma 2).

### The S block (`SProc.lean`)

| mode, S hole | condition | what the machine does | lemma |
|---|---|---|---|
| prime, index `a + 1` | `m + 1` prime | hole one cell left, run right, write `F := 1`, go home to copy (`hc1`) | `s_prime` |
| composite, index `a + 1` | composite, not a square | hole one cell left, go home (`hg1`); `F` untouched | `s_comp` |
| composite, index 0, `F = 1` | `m + 1 = (n + 1)²`, a prime was seen | fill the hole, run right; the 0 after the guard becomes the new hole and the `F` cell (a 1) the new right guard: region `2n + 3`, hole at the last index, new `F` cell blank | `s_square` |
| composite, index 0, `F = 0` | `m + 1 = (n + 1)²`, no prime seen | step into `halt` | `s_halt` |

Prime mode never meets an S hole at index 0, because `m + 1` would be both prime and a square
(Lemma 4); the machine has no transition for that case (`sC` on 0). `HaltAt c` means `c`
reaches the explicit `halt` state; `HaltAt.halts` turns it into `Halts`.

### Going home (`Home.lean`)

`Clean3` is the set of words made of 1s and runs of one to three 0s, each run followed by a 1.
Both homing routines (`hg1…hg4` and `hc1…hc4`, the structure `Home4`) walk left over 1s,
counting 0s, and stop at the fourth 0 in a row.

**Lemma 6 (homing, `Home4.cross`, `home_chk`).** Going left over a `Clean3` word leaves it
unchanged. `home_chk`: from `hg1` with a `Clean3` word `w` between the head and the tape's
leftmost 1, the machine reaches `chkW` of the whole tape, i.e. the next checkpoint. The words
crossed are `Clean3` because the only run of more than three 0s is the left end
(`Clean3.revblk`, `Clean3.pzR`, `zoneW_clean` in `Tape.lean`/`Cycle.lean`).

### Copying M (`Copy.lean`)

After a prime-mode sweep, the old `M` has `m + 3 = p + 2` cells for the new prime `p = m + 1`:
exactly a block of `p` without its hole. The copy routine makes a new `M` to its left and puts
the old `M`'s hole at the last index.

* `home_copy`: home (`hc1…hc4`), write two 1s (the new `M` starts with two cells), skip `00`,
  and put a cursor (a 0) on region index 0 of the old `M`. The copy state is `cpyC u v nm k Z`:
  new `M` with `nm` cells, `00`, old `M` with the cursor followed by `k` ones and the guard.
* `cpy_step`: one round trip adds a cell to the new `M` and moves the cursor one cell right.
* `cpy_last`: when the cell after the cursor is the guard, the cursor stays (it is now the
  hole, at the last index) and the machine heads home in `hg1`.
* `cpy_all`: by induction on `k`, after `m` rounds the new `M` has `m + 3` cells and the old
  `M` is the block `(m, 0)` of the new prime.

## Part 3: one increment, all cases (`Cycle.lean`)

**The checkpoint invariant.**

```lean
def Inv (m n : Nat) (f : Bool) : Prop :=
  1 ≤ n ∧ n*n ≤ m ∧ m < (n+1)*(n+1) ∧ (f = true ↔ ∃ p, PrimeDvd p ∧ n*n < p ∧ p ≤ m)
```

So `n = ⌊√m⌋` and `f` says whether a prime lies in `(n², m]`. The tape part (every residue, the
S hole, `F`) is not in `Inv`: it is built into the configuration `chk m n f`, whose tape `CW`
is computed from `m`, `n`, `f`. Each case below proves that the machine reaches
`chk (m + 1) n' f'` exactly (as an equality of tapes, `eW`) and that `Inv` holds again. All
reachability is *strict* (`Rch1`, at least one step, via the first step `chk_step` and
`from_step`).

| case | next checkpoint | why `Inv` holds again | lemma |
|---|---|---|---|
| `m + 1` prime | `chk (m+1) n true` | `m + 1` itself is a prime in `(n², m + 1]` | `cyc_prime` |
| composite, `m + 1 ≠ (n+1)²` | `chk (m+1) n f` | primes in `(n², m + 1]` are those in `(n², m]` | `cyc_comp` |
| `m + 1 = (n+1)²`, `f = true` | `chk (m+1) (n+1) false` | `(n+1)² < p ≤ (n+1)²` is empty | `cyc_square` |
| `m + 1 = (n+1)²`, `f = false` | halts (`HaltAt`) | — | `cyc_halt` |

`cyc_prime` uses: sweep in prime mode (Lemma 2), `s_prime`, `home_copy`, `cpy_all`, `home_chk`,
and Lemma 3 for the new block list. `cyc_comp` and `cyc_square` use the composite sweep,
`s_comp` or `s_square`, and `home_chk`.

**Lemma 7 (`cycle`, in `Main.lean`).** If `Inv m n f`: when `m + 1 = (n+1)²` and `f = false`,
the machine halts from `chk m n f`; otherwise it strictly reaches some `chk (m+1) n' f'` with
`Inv (m+1) n' f'`.

## Part 4: the main theorem (`Main.lean`)

**The seed** (`seed_reach`, `inv_one`). Eleven states write `111 000 11101` and go home: the
machine reaches `chk 1 1 false`, and `Inv 1 1 false` holds (no prime in `(1, 1]`). So the
first number tested is 2.

**All checkpoints are reached** (`reach_all`). By induction on `k`: either the machine has
already halted (`HaltAt start`) or it reaches `chk (k+1) n f` with `Inv (k+1) n f` for some
`n`, `f`.

**A counterexample makes it halt** (`haltAt_of_counterex`). Let `n₀` be a counterexample
(`Counterex`). Run to checkpoint `m = (n₀+1)² − 1 = n₀² + 2n₀`. There `Inv` forces `n = n₀`
(the square root is unique) and `f = false` (a prime in `(n₀², m]` would be a prime strictly
between `n₀²` and `(n₀+1)²`). Then `cyc_halt` applies.

**Halting gives a counterexample** (`halts_iff_dvd`). Suppose the machine halts but there is
no counterexample. Then at no checkpoint can the halting case of Lemma 7 occur: `m + 1 = (n+1)²`
with `f = false` would mean, by `Inv`, that no prime lies in `(n², m] = (n², (n+1)²)`. So
from every checkpoint satisfying `Inv` the machine strictly reaches another one, and
`not_halts_of_progress` (`Core/Sys.lean`) says it never halts from `chk 1 1 false`. Since the
machine is deterministic and `start` reaches `chk 1 1 false`, it would not halt from `start`
either (`halts_det`) — a contradiction.

`halts_iff_dvd` states the theorem with `PrimeDvd`; `halts_iff` rewrites it with
`primeDvd_iff` (and `sq_eq`: `n ^ 2 = n * n`).

## Part 5: the divisor form of primality (`Math.lean`, `Defs.lean`)

Inside the proof primality is

```lean
def PrimeDvd (p : Nat) : Prop := 2 ≤ p ∧ ∀ d, d ∣ p → d = 1 ∨ d = p
```

because the sieve arguments are about divisors: `exists_prime_dvd` takes a divisor of a
divisor (`Nat.dvd_trans`), `not_prime_iff` turns "not prime" into "has a divisor other than
1 and itself", `sq_not_prime` exhibits the divisor `n + 1`. The statement uses
`TinyCryptids.Prime` (trial division by `2 … p − 1`). They are equivalent (`primeDvd_iff`, which is
`TinyCryptids.prime_iff_dvd` from `Defs.lean`, reversed):

* *`Prime → PrimeDvd`.* Let `d ∣ p`. As `p ≥ 2 > 0`, `d ≤ p`, and `d ≠ 0` (0 divides only 0).
  If `d = 1` or `d = p`, done. Otherwise `2 ≤ d < p` and `p % d = 0`, which `Prime p` forbids.
* *`PrimeDvd → Prime`.* If `2 ≤ d < p` and `p % d = 0`, then `d ∣ p`, so `d = 1` or `d = p`,
  both impossible.

So the two theorems are stated in the repository's common definition of `Prime` (the same
statement as `TM.Legendre.halts_iff`), and the switch costs one rewrite.

## Part 6: the 45-state machine (`M45.lean`)

`M45` is obtained from the design by merging states that never disagree on a transition the
run uses (an exact SAT search, `../tools/minimize.py`). `M45.lean` is generated by
`gen_reduced_lean.py`: it gives the merged table `delta2`, a map `phi` from design states to
merged states, and a check `compat` (one case per state and symbol, closed by computation) that
`delta2 (phi q) b` does what `delta q b` does wherever the latter is defined. The generic lemma
`halts_iff_of_sim` (`Core/Basic.lean`) then shows the merged machine follows the design's run
step for step. Its one extra obligation — that when the design halts it does so where the
merged machine also has no transition — is met by `haltAt_of_false`: on a counterexample the
design reaches the explicit `halt` state, which maps to `halt2`, which has no transitions.

## What the proof does not cover

* It says nothing about whether Legendre's conjecture is true — that is the open problem. If it
  is true, the machine runs forever, and the proof shows exactly that.
* The design has other undefined transitions besides `halt` (e.g. `sC` on 0, prime mode
  meeting a wrapped S). The proof shows the run never reaches them; it does not say what the
  machine does from other tapes.
* Whether fewer states suffice: `RECORDS.md` notes that 44 states is unresolved.
* The annotated listing `machines/legendre_45_annotated.txt` is not part of the proof;
  `annotate.py` checks it against the machine file it was printed from. The Python tests
  (`test_inv.py`, `test_halt.py`) are independent sanity checks, not part of the proof.
