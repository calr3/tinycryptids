# A Turing machine for Legendre's conjecture

**Current best: `machines/legendre_45.txt`, a 45-state, 2-symbol Turing machine**
(named-state format, as in `../fermat/`). Started on a blank tape, it **halts iff
Legendre's conjecture is false**: iff for some `n ≥ 1` there is no prime `p` with
`n² < p < (n+1)²`. Otherwise it runs forever. Lean proves this
(`TM.LegendreSieve.M45.halts_iff`), with no Mathlib and no assumption about primes beyond the
definition. `RECORDS.md` lists every machine with its state count and Lean theorem. `PROOF.md` walks through the proof in plain words.

(A search can only halt when it finds a counterexample, so "halts iff Legendre is
false" is the version that does not depend on the conjecture.)

The 45-state machine is obtained in two stages:

1. `legendre.txt` is the readable **68-state design**, generated by `build.py`.
   The Lean proof is written for this machine (`TM.LegendreSieve.halts_iff`).
2. `minimize.py` merges states of the design that never disagree on a transition
   the run actually uses (an exact SAT search), giving 45 states. The proof
   carries over automatically. `machines/legendre_45_annotated.txt` is the
   45-state machine with each state named after its roles in the design.

## How it works

It is an incremental sieve that checks `m = 2, 3, 4, …` in order. At checkpoint
`m` the tape is

    M 00 P_k 00 … 00 P_1 000 S 0 F

* `M = 1^(m+2)` is a plain counter, the only block without a hole.
* `P_i`: one block per prime `p ≤ m`, largest first: a 1, a region of `p` cells
  containing one **hole** (a single 0), and a 1. The hole sits at region index
  `p-1-(m mod p)`, so it moves one cell left per step and wraps from index 0 to
  index `p-1` exactly when `p` divides the new `m`.
* `S`, the square counter, has the same shape with a region of `2n+1` cells
  (`n = ⌊√m⌋`) and the hole at index `2n-(m-n²)`. It wraps exactly when the new
  `m` is a square.
* `F` is one cell: 1 iff a prime has appeared since the last square `n²`.
* The `000` before `S` is the only run of exactly three 0s. The left end of the
  tape is the only run of four or more.

One step `m → m+1`:

1. **Home**: go left until four 0s, write a 1 there (`M` grows), turn round.
2. **Sweep** right over the P blocks, moving each hole one cell left, or
   wrapping it. A wrap means that prime divides `m+1`. From then on the sweep
   runs in a second copy of its states ("composite mode"). The `000` ends it.
3. **S**, composite mode: move the hole. If it wraps, `m+1 = (n+1)²`. If
   `F = 0` there was no prime in `(n², (n+1)²)`, so the machine **halts**. If
   `F = 1`, the F cell itself becomes S's new right guard: the region grows by 2
   and F is cleared at no cost.
   **S**, prime mode (no block wrapped, so `m+1` is prime and not a square):
   move the hole, set `F`, go home and **copy M** to its left. The old `M` has
   length `p+2` for the new prime `p = m+1`, so putting its hole at the last
   index (residue 0) turns it into `P_{k+1}`.

The seed writes the tape for `m = 1`, `111 000 11101` (11 states).

State budget of the 68-state design: seed 11, home and grow 7, sweep 17
(7 per mode plus 3 for a wrap), S after a prime-mode sweep 8, S after a
composite-mode sweep 8, home and copy 17.

## Files and checks

* `build.py` generates the design (`python3 build.py legendre.txt`).
  The shared tools are in `../tools/`: `tm.py` parses the format and converts it to
  bbchallenge standard text; `sim.c` is the fast simulator
  (`gcc -O2 -o ../tools/sim ../tools/sim.c`).
* `test_inv.py N`: runs from a blank tape and checks the **whole tape** at each
  of the first N checkpoints against the invariant above (every residue, S, F).
  Checked up to N = 3000 (3.6·10⁹ steps).
* `test_halt.py`: a variant that never sets F halts at m = 4. Every checkpoint
  tape for 2 ≤ m < 400 is placed with F forced to 0 and then to 1. The machine
  must halt exactly when F = 0 and no prime comes before the next square.
* `../tools/same_run.py A B k`: two machines have identical tapes after 10³…10ᵏ steps.
* `../tools/minimize_dimacs.py in out [K]`: exact merging, encoded as SAT. It writes DIMACS and
  runs an external solver binary (`MIN_SOLVER=/path/to/kissat`, or cadical), so
  it needs no Python packages. `../tools/greedy_merge.py` is a fast randomised estimate
  (46 states here).
* `annotate.py merged out Name`: the readable listing.
* `gen_lean.py` writes `../lean/TinyCryptids/LegendreSieve/Machine.lean`;
  `gen_reduced_lean.py machines/legendre_45.txt M45` writes `M45.lean`.

## Formal proof (Lean 4)

`../lean/TinyCryptids/LegendreSieve/` contains a complete, machine-checked proof of

```lean
theorem TM.LegendreSieve.halts_iff :
    Halts delta start ↔ ∃ n, 1 ≤ n ∧ ∀ p, n ^ 2 < p → p < (n + 1) ^ 2 → ¬ TinyCryptids.Prime p
```

where `delta` is the 68-state design (`Machine.lean`, generated by `gen_lean.py`),
`TinyCryptids.Prime p := 2 ≤ p ∧ ∀ d, d < p → 2 ≤ d → p % d ≠ 0` (`../lean/TinyCryptids/Defs.lean`,
the same statement as `TM.Legendre`), and the same statement
`TM.LegendreSieve.M45.halts_iff` for the 45-state machine. It uses Lean 4.15.0 core
only. `cd ../lean && lake env lean Check.lean` prints the axioms:
`propext`, `Classical.choice`, `Quot.sound`.

| File | Contents |
|------|----------|
| `../Core/` | TM semantics on stream tapes, scanning lemmas (shared by all machines) |
| `Tac` | one-step tactics |
| `Sweep` | a block's hole move and wrap, induction over the P zone |
| `SProc` | the S block in prime mode, composite mode, square growth, halting |
| `Home` | going home over a `Clean3` word (runs of ≤ 3 zeros), the checkpoint |
| `Copy` | copying M, by induction on the cursor |
| `Math` | primes in divisor form (`PrimeDvd`, `primeDvd_iff : PrimeDvd p ↔ TinyCryptids.Prime p`), `primesDesc`, a sieve step on the residues, `m+1` composite iff some prime `≤ m` divides it |
| `Tape` | the tape as a list (`CW m n f`), its `Clean3` facts, the sweep from a checkpoint |
| `Cycle` | one step: the prime, composite, square and halting cases |
| `Main` | the seed, `cycle`, and the main theorem |
| `M45` | the 45-state machine (generated by `gen_reduced_lean.py`) |

The checkpoint invariant `Inv m n f` says `n ≥ 1`, `n² ≤ m < (n+1)²`, and
`f = true ↔ ∃ prime p, n² < p ≤ m`. The direction "halts → counterexample" uses
`not_halts_of_progress`: without a counterexample, every checkpoint strictly
reaches the next one. The other direction runs the cycle up to `m = (n+1)² - 1`.
