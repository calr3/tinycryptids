# A Turing machine for the Sierpiński problem (below 78557)

A [Sierpiński number](https://en.wikipedia.org/wiki/Sierpi%C5%84ski_number) is an odd number k such that `k·2^n + 1` is [composite](https://en.wikipedia.org/wiki/Composite_number) for all n.
The Sierpiński conjecture is that 78,557 is the smallest Sierpiński number. This machine halts iff that is the case.

**Current best: `machines/sierpinski_60.txt`, a 60-state, 2-symbol Turing machine**
(named-state format, see `../tools/tm.py`). Started on a blank tape, it **halts iff no odd
k < 78557 is a Sierpiński number**: iff every odd `k < 78557` has some `n ≥ 1` with
`k·2^n + 1` prime. Lean proves this (`TM.Sierpinski.M60.halts_iff`):

    Halts M60.delta2 M60.start2 ↔
      ∀ k, k % 2 = 1 → k < 78557 → ∃ n, 1 ≤ n ∧ Prime (k * 2 ^ n + 1)

where `Prime p := 2 ≤ p ∧ ∀ d, d < p → 2 ≤ d → p % d ≠ 0` (`TinyCryptids.Prime`,
`../lean/TinyCryptids/Defs.lean`). `RECORDS.md` lists the machines, and `PROOF.md` walks
through the proof in plain words.

The statement is Σ₁ ("for each of finitely many k there is an n"), so unlike the other
machines this one halts iff the statement is **true**. 78557 is a Sierpiński number (every
`78557·2^n + 1` has a factor among 3, 5, 7, 13, 19, 37, 73), and it is conjectured to be the
smallest; the machine halts iff that is so. At the time of writing five `k` below it have no
known prime (21181, 22699, 24737, 55459, 67607).

The 60-state machine is obtained in two stages:

1. `sierpinski.txt` is the readable **83-state design**, generated by `build.py`. The Lean
   proof is written for this machine (`TM.Sierpinski.halts_iff`).
2. `../tools/minimize.py` merges states of the design that never disagree on a transition the
   run uses (an exact SAT search). `gen_reduced_lean.py` carries the theorem over, and
   `machines/sierpinski_60_annotated.txt` is the same machine with each state named after its
   roles in the design.

## The search

    for k = 3, 5, ..., 78555:            (k = 1: 1·2 + 1 = 3 is prime)
        for n = 1, 2, ...:
            if k·2^n + 1 is prime: next k
    HALT

Trial division by a mod walk. There are no multiplications: the next candidate for the same
`k` is `2P − 1` (P doubled in unary), and the first candidate for the next `k` is built from a
copy of K.

The constant 78557 itself has to be stored: halting at the first `k` with a covering set would
need a Lean computation over all smaller `k`, and since 67607 is still open the bound cannot be
lowered to a power of two (65536) with the `k` above it proven by explicit primes.

## How it works

The tape, left to right (blocks of 1s, a hole is a single `0` inside a block):

    C 0 K 0 D 00 R

* **C** is a binary counter: four groups of four bits `b3 b2 b1 b0`, each followed by a marker
  1, most significant group first (20 cells). It holds the number of `k` still to come.
* **K** has `k + 6` cells while `k` is tested.
* **D** has `d + 1` cells (cells `0 … d`), the trial divisor `d`. Its hole steps cyclically over
  cells `1 … d`; its **home** is cell `d`, D's last cell.
* **R** has `r + 1` cells, `r = P − d`. During the mod walk its hole steps from cell 0 (where it
  makes a run of three 0s with the separator) to cell `r − 1`.

**Trial division.** For `d = 3, 4, …` (P is odd): the mod walk advances the D hole `r` times,
one step per step of the R hole (from D's last cell it wraps to cell 1); then `d | P` iff the D
hole is home. The walk ends right of R, so the head comes back over R and the separator and
reads D's last cell: 0 is a divisor, and P is composite. Otherwise the hole is filled, and the
**shift** needs no work on D: the first cell of the separator becomes D's new last cell, and it
is already 0, i.e. the hole is home again (`d := d + 1`). R loses its cell 0 (`r := r − 1`) and
gets its hole at its new cell 0; if R is then a single cell, `r = 0` and P is prime.

**The loop** (`s1 … s7c`) is the one routine that copies. Let X be a block whose last cell is
under the head, with blocks X' and T to its right, single 0s between them (both empty at
first). One round erases the last cell of X; it reappears as the first cell of X' (X' grows to
the left), and one more cell is appended to T. The loop stops at the first 0 it meets in X. So
X ends up moved one cell to the right as X', and T is a copy of it. `t1` reads the cell left of
the stop: 0 (the separator) for R, C's lowest marker for K.

**Composite** (`x1 … g7`, `a1 … a6`). Fill the hole and the separator; then from D's cell 1,
D := 3 (cells 1, 2, its hole home at cell 3), the separator, and R's hole at R's cell 0, which
leaves `P − 2` cells for R; then run the loop on R: it stops at R's hole. Filling the gap left by
the loop and the X'/T separator joins R, X' and T: R gets `2|R| + 1` cells, so the next
candidate is `3 + 2|R| = 2P − 1 = k·2^(n+1) + 1`. The R hole is already at cell 0 for the next
mod walk.

**Prime** (`w1 … w3`, `Dm … ret`, `b2 … b6`). Wipe D and R (no hole left in D to step around)
and append a cell to K, then run the loop on K: it stops at the separator left of K. Then
decrement C: the borrow runs through the groups; if it runs past the top group, C was 0 and
the machine **halts** (this happens after `k = 78555`). Filling the cell left of K' gives K two
more cells (`k := k + 2`). T, a copy of the old K, becomes D := 3 and R from its cell 1 (`g1`),
and the loop doubles R: the first candidate for the new `k` is `2k + 1`.

**The seed** writes C (39278) and K for the step to `k = 1`, two cells shorter than the step to
`k = 3`. Its region lacks R's cell 0, which `g6` makes as the hole on a blank cell; the
candidate is then 5, a prime, and the step to `k = 3` follows. This pseudo-round saves two
seed states (a run of 1s that merges with nothing).

State budget of the 83-state design: seed 27, mod walk and divisor test 16, shift 6, composite
4, D := 3 and the R hole 7, wipe 3, loop 7, end of the doubling 4, counter 6, new k 3.
