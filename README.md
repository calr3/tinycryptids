# Small Turing machines for open problems, proven in Lean

Each folder holds a Turing machine that refers to a notable mathematical conjecture. The machines are designed so that their halting behaviour implies something about the conjecture; exactly what depends on its place in the [arithmetic hierarchy](https://en.wikipedia.org/wiki/Arithmetical_hierarchy). For example:

* For class Π₁, the machine halts iff the conjecture is false
* For class Σ₁, the machine halts iff the conjecture is true
* For class Π₂, the [beeping machine](https://wiki.bbchallenge.org/wiki/Beeping_Busy_Beaver) quasihalts iff the conjecture is false
* For class Σ₂, the beeping machine quasihalts iff the conjecture is true
* For class Π₃, the [beeping booping machine](https://wiki.bbchallenge.org/wiki/Beeping_Busy_Beaver#Beeping_Booping_Busy_Beavers) pseudoquasihalts iff the conjecture is false

and so on. These results are interesting because determining the value of the [Busy Beaver function](https://wiki.bbchallenge.org/wiki/Main_Page) `BB(n)` implies solving all conjectures of size `n` or less in Π₁ and Σ₁ (and likewise `BBB(n)` for Π₂ and Σ₂). For example, we now know that evaluating `BB(21)` requires us to [solve Goldbach's Conjecture](https://github.com/google-deepmind/cryptids/tree/main/artifacts/goldbach_21), alongside many other difficult problems! See the [BusyBeaverWiki](https://wiki.bbchallenge.org/wiki/Cryptids#Larger_Cryptids) for many other interesting examples and strongest-known results.

Each machine in this repository comes with the specific Turing Machine code, a human-readable summary, and a formalized proof in Lean 4 (core library only, no Mathlib) showing that the machine has the required behaviour; run
`cd lean && lake build && lake env lean Check.lean` to check them all.

The state count is the number of states required by the smallest known machine, as given by the output of the fully minimized machine (`minimize.py` or `minimize_clique.py`) from the design given in the folder's `build.py`.
The BBi column gives the same machine's instruction count: its number of defined transitions, with the halting transition left undefined as BBi requires (so one fewer than the counts elsewhere in this repository, such as `pa_nsymbols/`, which include it).
Each folder's `RECORDS.md` lists every machine, `README.md` explains the algorithm and gives the machine in bbchallenge standard text, `PROOF.md` walks through the proof in plain words, and `machines/*_annotated.txt` describes every state.

† Fermat's Last Theorem is of course a theorem since [Wiles (1994)](https://en.wikipedia.org/wiki/Wiles%27s_proof_of_Fermat%27s_Last_Theorem), so any non-halting machine would do. This more direct machine is included as a historical curiosity, because James Randels' dissertation *Studies in Turing Machines* (1965) suggested a construction it (without a full description) that he estimated at under 400 states. This machine (and its proof) do not use Wiles's result.

‡ The PA machines halt on a proof of `v0 ∈ v0` in a theory T (Tarski's first-order logic with `=` and `∈`, plus a set existence scheme of H. Friedman). T proves `¬ v0 ∈ v0`, so they halt iff T is inconsistent. The Lean theorems are about T (`Wff.Provable` in `lean/TinyCryptids/Defs.lean`); that T is equiconsistent with PA is Friedman's result and is not formalised. These machines are compiled from a register program rather than designed by hand: `pa/` improves on LegionMammal978's 372-state [`pa.py`](https://github.com/LegionMammal978/turing_machine_explorer), built with A. J. Wade's TMBuilder, and `pa_nsymbols/` uses 10 symbols to lower the number of instructions (defined transitions) from 616 to 469. `pa_nsymbols/` also has machines for 5 to 14 symbols, tested by simulation only.

## Layout

| Path | Contents |
|------|----------|
| `<conjecture>/` | One hand-designed machine: `build.py`, tests, `machines/`, `README.md`, `RECORDS.md`, and `gen_lean.py`/`gen_reduced_lean.py`/`annotate.py` |
| `pa/`, `pa_nsymbols/` | The PA machines, compiled from the register program `pa/program.py` (by `pa/tmbuilder.py` for 2 symbols, `pa_nsymbols/kary.py` for more), with tests and the generators of their Lean proofs |
| `lean/` | **All proofs**, one Lake project: `TinyCryptids/Core/` (the shared machine model), `TinyCryptids/Defs.lean` (every definition used in a statement), `TinyCryptids/<Machine>/` (namespace `TM.<Machine>`), `Check.lean`. See `lean/README.md` |
| `tools/` | Shared Python tools: `tm.py` (format, standard text), `sim.c` (`gcc -O2 -o tools/sim tools/sim.c`), `same_run.py`, `minimize.py`, `minimize_clique.py`, `minimize_dimacs.py`, `greedy_merge.py`, `greedy_merge_par.py` (parallel, with exclusive beep/boop transitions), `synth_round.py`, `leangen.py`, `bbi.py` (the BBi column) |
