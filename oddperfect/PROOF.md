# The proof, in plain words

This is a guided tour of the Lean proof that the 37-state machine
`machines/oddperfect_37.txt` halts if and only if an odd perfect number exists. The proof is
in `../lean/TinyCryptids/OddPerfect/` (about 620 hand-written lines, plus the two generated
machine listings) and uses the generic routines of `../lean/TinyCryptids/Core/`; each step
below names the lemma that carries it.

## What is proved

```lean
theorem TM.OddPerfect.halts_iff :
    Halts delta start ↔ ∃ n, n % 2 = 1 ∧ properDivSum n = n

theorem TM.OddPerfect.M37.halts_iff :
    Halts M37.delta2 M37.start2 ↔ ∃ n, n % 2 = 1 ∧ properDivSum n = n
```

* `properDivSum n` is `divSumBelow n n`, where `divSumBelow n k` adds up the numbers
  `e ≤ k` with `e < n` and `e ∣ n` (`../lean/TinyCryptids/Defs.lean`). So it is the sum of the
  proper divisors of `n`, and `properDivSum 1 = 0`. The right-hand side says: some odd `n` is
  perfect. (`n = 1` is automatically excluded.)
* `Halts δ c` means: started in configuration `c`, the machine reaches a configuration with
  no transition (`../lean/TinyCryptids/Core/Basic.lean`, the model shared by every machine in the
  repository: 2 symbols, a two-way infinite tape, the head always moves).
* `delta`/`start` is the 50-state design `oddperfect.txt` (`Machine.lean`, generated by
  `gen_lean.py`); `M37.delta2`/`M37.start2` is the 37-state machine (`M37.lean`, generated by
  `gen_reduced_lean.py`). Both start in their first state on a blank tape. Each table has one
  extra constructor, `halt` / `halt2`, with no transitions; it is the halting state, not
  counted among the 50 or 37.

To trust the result you need to trust the Lean kernel, the definitions above, and the listing
of the machine. Nothing else: both theorems depend only on Lean's standard axioms `propext`,
`Classical.choice` and `Quot.sound` (`../lean/Check.lean` prints this).

The proof has four parts: arithmetic (`Spec.lean`), one round of the machine on the tape
(`Round.lean`, using `Core/Routines.lean` and `Core/Lemmas.lean`), the main theorem for the
50-state design (`Main.lean`), and the transfer to the 37-state machine (`M37.lean`).

## The idea

The machine runs **rounds** `n = 1, 3, 5, …`. In round `n` it tries every candidate divisor
`d = 1, …, n − 1`, keeps a running sum `s` of the divisors found, and at the end halts iff
`s = n`. Everything is unary. The candidate `d` and the rest `n − d` sit in two adjacent
blocks, so `d → d + 1` is just "move the separator one cell right". Divisibility is tested by
walking a hole cyclically around the `d` block once per cell of the other block: it is back
home iff `d ∣ n − d`, the same as `d ∣ n`. The sum is a hole in a third block, moved `d`
cells for each divisor; it **saturates** at `n + 1`, so this block never needs more than
`n + 3` cells, and "saturated value = `n`" still means exactly "`s = n`". If an odd perfect
number exists, the machine halts at the first one; if none exists, every round passes to the
next and the machine runs forever. There is no termination subtlety: every round finishes.

## Part 1: arithmetic (`Spec.lean`)

**Lemma 1 (`properDivSum_eq`).** For `n ≥ 1`, `properDivSum n = divSumBelow n (n − 1)` (the
term `e = n` contributes nothing).

**Lemma 2 (one candidate, `divSumBelow_step`, `sub_mod_self`).** For `1 ≤ d < n`,
`divSumBelow n d = divSumBelow n (d − 1) + (d if (n − d) % d = 0, else 0)`.

**Lemma 3 (`mod_succ`).** `(x + 1) % d` is `x % d + 1` if that is `< d`, and 0 if it equals
`d`. This is what the cyclic hole does.

## Part 2: one round on the tape (`Round.lean`)

**The tape.** During round `n` the tape is three blocks of 1s separated by `00`:

    T 00 D 00 R

* `T` has `L + 1` cells, `L = n + 2`, with a hole (a single 0) at cell `u + 1`, `u ≤ L − 1`:
  a counter `u`. Seen from its right end it is `TX L u` (`L − 1 − u` ones, the hole, `u + 1`
  ones). At `u = L − 1` the hole is T's last cell, next to the separator: three 0s in a row.
* `D` has `d + 1` cells (cells `0 … d`) and holds the candidate `d ≥ 1`; during the walk its
  hole is at cell `h`, `1 ≤ h ≤ d`. Cell `d`, the last one, is the hole's **home** (counter 0).
* `R` has `r + 2` cells, `n = d + r + 1`; during the walk its hole is at cell `j ≤ r`.

Navigation is done by 2-state **parsers** that move over 1s and `00` separators and stop at
the first single 0 (`ParserR`, `ParserL` in `Core/Lemmas.lean`). A hole next to a separator
makes a run of three 0s; `ParserR.find3` / `ParserL.find3` cross such a run from the side
where the hole is the far end, and `ParserR.findS` / `ParserL.findS` combine both cases. The
design has six parsers: `PPR`, `PPA`, `PPZ` (rightwards) and `PPM`, `PPT`, `PPC` (leftwards).

**The checkpoints** (`Y` is the tape left of D's separator; in a round `Y = F ::: TX L u`):

* `MW Y d r h j` — mod walk: head on the D hole at cell `h`, R hole at `j`, state `ma1`.
* `E3 Y d r h` — the walk is over: head on D's home, D hole at `h`, state `e3`.
* `AD L u d r c` — adding: head on the D hole at cell `c`, which moves down, state `a1`.
* `SEP Y d r` — head on the first separator cell, D without hole, state `f2`.
* `RE Y n` — the round for `n` is over: D has `n` cells and its home, state `f6`.
* `HaltAt c` — `c` reaches a configuration in state `halt`. `HaltAt.halts` turns it into
  `Halts`; `HaltAt.back` pulls it back along `Rch`.

**Lemma 4 (the mod walk, `dadv`, `mw_step`, `mw_upto`, `mw_last`, `walk`).** These are
`../Sierpinski/Round.lean`'s lemmas (the same states), extended to `d = 1`. `dadv` advances
the D hole from `h` to `h % d + 1` (from home it runs back over D to cell 1); `mw_step` is one
round (advance D, parse right to the R hole, move it, parse back); after `r + 1` rounds the R
hole falls off and the machine runs back over R to D's home (`mw_last`). Together
(`walk`): `MW Y d r d 0` reaches `E3 Y d r (r % d + 1)`, and the D hole is home iff
`(r + 1) % d = 0`, i.e. iff `d ∣ n`.

**Lemma 5 (not a divisor, `fill_hole`).** For `h < d`, `E3 Y d r h` reaches `SEP Y d r`: the
hole is filled on the way left, then the machine runs right over D.

**Lemma 6 (adding `d`, `add_unit`, `add_step`, `add_first`, `add_all`, `add_end`, `add`).**
Each unit moves the D hole one cell down, parses left to the T hole, advances it and parses
right back to the D hole. The T advance: fill the hole, and write a new one on the next cell —
unless the next cell is the separator (the hole was T's last cell), in which case `t2` writes
the hole back where it was. So `u` becomes `min (u + 1) (L − 1)` (`add_unit`). The first unit
starts from `e3` on the home (`add_first`), the next ones from `a1` (`add_step`); after the
unit for cell 0 the D hole falls off and the machine runs right over D (`add_end`). In all
(`add`): `E3 (F ::: TX L u) d r d` reaches `SEP (F ::: TX L (min (u + d) (L − 1))) d r`.

**Lemma 7 (shift, `shift`, `shift_end`).** `SEP Y d (r + 1)` reaches `MW Y (d + 1) r (d + 1) 0`:
the first separator cell stays 0 and becomes D's new home, R's cell 0 becomes the separator,
and its next cell the new R hole. With `r = 0` the same moves end on a blank cell: `RE Y (d + 1)`.

**Lemma 8 (one candidate, `dstep`).** By Lemmas 4–6: `MW (F ::: TX L u) d r d 0` reaches
`SEP (F ::: TX L u') d r` with `u' = min (u + d) (L − 1)` if `(r + 1) % d = 0`, else `u`.

**Lemma 9 (the round end, `re_fill`, `check`, `reset`, `round_end`).** From `RE` the machine
writes six 1s from the right (the new R's cells), runs back over D, marks D's cell 1 with a 0
(`re_fill`), and parses left to the T hole (`check`):

| T counter `u` (with `L = n + 2`) | the two cells after the hole | result |
|---|---|---|
| `u = L − 1` (saturated) | the separator | fill, go on |
| `u = L − 2`, i.e. `u = n` | `1`, then the separator | **halt** (`x3` → `halt`) |
| `u < L − 2` | `1 1` | fill, go on |

Otherwise (`reset`) the machine runs left to T's end, writes one cell two cells further left
(the cell in between is the new hole: T gains two cells and its counter is 0), parses right to
the mark, and turns the mark into D's home: `D := 1`, the separator, R's hole at its cell 0.
So for `u ≠ n`, `RE (F ::: TX (n + 2) u) n` reaches `MW (F ::: TX (n + 4) 0) 1 n 1 0`, the
round for `n + 2` (`round_end`).

**Lemma 10 (seed, `seed_reach`).** The seven seed states write `10 00 1`: T for a
pseudo-round `n = −1` (two cells, the hole on the last), the separator and D's cell 0, and
step onto the round end. The round end's moves (with `check` for `L = 1`: saturated, and
`reset`) reach `RE (F ::: TX 3 0) 1`: the end of the round for `n = 1`, which has no
candidate.

## Part 3: the main theorem for the design (`Main.lean`)

Define `RN n := RE (F ::: TX (n + 2) (min (properDivSum n) (n + 1))) n`: the end of the round
for `n`, with T holding the (saturated) sum of the proper divisors of `n`.

**Lemma 11 (all candidates, `dloop`).** For `n ≥ 2`, starting at candidate `d` with counter
`min (divSumBelow n (d − 1)) (n + 1)`, the machine reaches `RN n`. *Proof:* induction on
`n − 1 − d`; each candidate is one `dstep` followed by `shift` (or `shift_end` for the last
one, `d = n − 1`). The local fact `upd` says the counter update agrees with Lemma 2; the key
identity is `min (min s (n + 1) + d) (n + 1) = min (s + d) (n + 1)`, so saturation commutes
with adding.

**Lemma 12 (a round, `cycle`).** For `n ≥ 1`: if `properDivSum n = n`, then `HaltAt (RN n)`;
otherwise `RN n` strictly reaches `RN (n + 2)`. *Proof:* `round_end` with
`u = min (properDivSum n) (n + 1)` (`u = n` iff `properDivSum n = n`), then `dloop` for
`n + 2` from `d = 1` (where `divSumBelow (n + 2) 0 = 0`). The two configurations differ
(`RE_ne`), so the run takes at least one step (`reach1_of_ne`).

**Halting gives an odd perfect number.** Suppose there is none. Then for every `m`,
`2m + 1` is not perfect, so `RN (2m + 1)` strictly reaches `RN (2m + 3)` (Lemma 12). A machine
that keeps strictly moving between members of a family never halts
(`not_halts_of_progress`, `Core/Sys.lean`), so `RN 1` does not halt. Since the machine is
deterministic and `start` reaches `RN 1` (`start_reach`, from Lemma 10 and
`properDivSum 1 = 0`), `start` does not halt either (`halts_det`) — contradiction.

**An odd perfect number makes it halt** (`haltAt_of_opn`). Let `n = 2M + 1` be odd and
perfect. By induction on `M − m`, each round `2m + 1` either halts (if that number is perfect)
or passes to the next, until round `n` halts by Lemma 12. So `start` reaches the state
`halt`. The result is the stronger `HaltAt start`, which Part 4 needs.

This is `TM.OddPerfect.halts_iff`, for the 50-state design `oddperfect.txt`.

## Part 4: the 37-state machine (`M37.lean`)

`M37` is obtained from the design by merging states that never disagree on a transition the
run uses (`../tools/minimize_clique.py`, an exact SAT search). `M37.lean` is generated by
`gen_reduced_lean.py`: it gives the merged table `delta2`, a map `phi` from design states to
merged states (for example `mw3 ↦ seed0`, `ra1 ↦ seed0`, `k3 ↦ t1`: every seed state also
does a step of another routine),
and a check `compat` (one case per transition, closed by computation) that
`delta2 (phi q) b` does what `delta q b` does wherever the latter is defined. The generic
lemmas `sim_run` and `halts_iff_of_sim` (`Core/Basic.lean`) then show that the merged machine
follows the design's run step for step. Two directions:

* if `M37` halts but the design does not, the design's run is still defined at that step,
  and `sim_run` maps it to a defined step of `M37` — contradiction;
* if an odd perfect number exists, the design reaches state `halt` (`haltAt_of_opn`), and
  `phi halt = halt2` has no transitions, so `M37` halts there too.

The second point is why the design proof establishes `HaltAt` and not just `Halts`: the
design's other undefined transitions are filled in by the merge, so only `halt2` is a halting
state of `M37`.

## What the proof does not cover

* It says nothing about whether an odd perfect number exists — that is the open problem. If
  none exists, the machine runs forever, and the proof shows exactly that.
* Even numbers are never examined (rounds go `1, 3, 5, …`), as the statement requires.
* The bbchallenge standard-text line in `README.md` and the annotated listing
  `machines/oddperfect_37_annotated.txt` are printed from the machine file; the Lean table
  `delta2` is generated from `machines/oddperfect_37.txt` and is what the theorem is about.
* `test_e2e.py` (tape comparisons up to `n = 341`, and an abundant-number test variant) is a
  test, not part of the proof.
